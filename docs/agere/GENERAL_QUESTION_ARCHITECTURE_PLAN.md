## One target architecture

Question + explicit saved context → requirement contract → source/definition discovery → typed analysis DAG → semantic and structural validation → deterministic execution → evidence-bound answer → saved result → optional simulated work/monitor.

All grammar, small-model and frontier interpreters propose the SAME contract. None is an independent answer authority. Reuse the current compiler and engine registry, extending their expressiveness as needed. Cache only contracts/results with the necessary source and dependency identities. Treat model prose as explanation of executed results, never the calculator or source of patient membership.

The contract must contain:

- Original wording, requirement IDs, literal evidence spans, semantic role and dependencies. Map every population, predicate, negation, exception, time anchor, output, grouping, comparison, attribution and requested method to executable nodes or an explicit unresolved requirement. Literal word coverage alone is insufficient.
- Entity grain and keys; typed Boolean tree; event time versus availability time; index date; units; observation windows; denominator and missingness policy; versioned clinical/metric/contract definitions. Record any user-visible default. Resolve materially ambiguous AND/OR or time scope before executing a potentially wrong population.
- An analysis DAG supporting intermediate named relations, joins with declared cardinality, semijoins/antijoins, aggregation, windows, temporal sequences and registered analytical methods. Cohorts are one result type; provider, facility, claim, program and contract analyses cannot all be reduced to a patient list.
- A separate optional workflow DAG for deliverables, synthetic actions and monitoring, bound to a specific result revision. An unresolved action need not erase valid analysis; unresolved eligibility must prevent creation of an allegedly eligible cohort.
- Per-output result status, execution/evidence receipts, and any unresolved dependencies. Overall answered requires all analytical requirements satisfied. Partial results explicitly identify answered clauses. Data absent, conflicting evidence, definition missing, method unsupported, interpretation failure and execution failure are distinct states.

## Token-economics design

Use deterministic execution for computation. Use deterministic parsing only when complete; otherwise choose the least costly QUALIFIED interpreter for the required contract, escalating on unresolved meaning or failed checks. Frontier interpretation remains available immediately when needed. Until cheaper paths are qualified, retain the capable path rather than claiming savings through refusals. Do not force every unfamiliar question through several independent frontier calls; assess the incremental benefit of reviewer calls and route them by measured failure risk. Keep the current checker until evidence supports changing it.

Retrieve compact relevant schema/definitions first, then expand on demand. Cache schema and evidence separately from interpretation and result caches. Include source/version, permissions, definition/operator dependencies, model/prompt, as-of semantics and saved context in identity as appropriate. Revalidation must invalidate changed dependencies. Relative dates cannot replay stale resolved windows. Corrections invalidate affected artifacts. Train/distill only on adjudicated training cases with provenance; no evaluation leakage or automatic promotion from user approval/model consensus.

Record request ID, attempt ID, source/code/definition hashes, route and reason, model, input/output/cache tokens, prices and pricing version, all reviews/retries/failures, cache classification, elapsed and stage time, SQL/engine execution, outcome and completeness. Unknown cost remains unknown. Report API marginal cost separately from local compute, ingestion/extraction/indexing, training and maintenance; amortize those only with explicit workload assumptions. Historical $0 replays do not erase prior acquisition cost.

## Proof protocol (G5)

These are proposed release thresholds, to be registered before opening final results. They are targets, not achieved scores. Keep benchmark-reference restrictions in force: no Gold-50/native-150 rerun or rescore until their selected references are independently validated. Never inspect hidden generator keys.

1. Establish independent references. An evaluator outside the implementation path writes expected results from received raw records and independently implemented calculations, with a second review of joins, units, dates, missingness and clinical/contract meaning. Do not use Agere operators as the oracle. Validate scorer behavior for extra/missing rows, duplicates, null versus zero, empty sets, units, multi-column tables and tolerances before scoring. Ambiguous cases get an adjudicated clarification expectation. Clinically uncertain questions remain uncertain.
2. Build a frozen challenge pack of 120 unseen base requests, stratified across clinical observations, population care, utilization, provider performance, access, finance, VBC/contracts and operations (15 each). Include at least 40 cross-domain questions, 24 structured-plus-unstructured questions, 24 sequential conversations and 24 independently established missing/ambiguous/unsupported cases; categories may overlap. Include newly combined methods, dates, exclusions, attribution and denominators. Add a separately prepared schema with renamed entities, new fields/streams and different relationships; permit generic metadata/adapters, no question-specific code.
3. Add three meaning-changing variants to each base request and two meaning-preserving paraphrases. Independently verify the expected effect, including cases where counts legitimately remain equal. Check patient/table identity and plan semantics, not just equal counts. A smaller evaluator-hidden fixture suite tests Boolean algebra, temporal boundaries, join multiplicity, corrections and follow-up scope exhaustively. Previously exposed review examples belong to development regressions, never the unseen denominator.
4. Freeze source snapshot, build, prompts, models/settings, definitions, question hashes, scorer and cache policy before execution. Run through the real compose path, with selected browser/save/reopen/action checks. Lock answers before adjudication. After tuning on failures, use a fresh sealed pack; do not call re-tested failures held out.
5. Report exact-set/table correctness, supported-question coverage, complete answer accuracy, correct abstention/clarification, false data-absence, unsupported claims, citation entailment, constraint retention, follow-up scope, latency p50/p95, cost and variability. Stratify by domain, complexity, model route, unseen composition and source mode. Refusal on an answerable question counts as a failure; an eloquent partial answer cannot count as complete.

Proposed engineering release gate: zero silently dropped constraints, wrong-scope actions, simulation leakage or fabricated evidence on the release suite; at least 95% complete correct outcomes overall, at least 90% in each domain, and at least 95% correct handling of independently unanswerable/ambiguous cases. Publish confidence intervals and sample size. Any critical observed failure blocks activation until fixed and independently rechecked. These finite gates do not certify universal or clinical reliability.

Fair economics: compare Agere with competent Haiku-, Sonnet- and frontier-based agents given identical snapshots, semantic definitions, retrieval, SQL, engines, permissions and output contracts. Allow equivalent caching and tool budgets; document prompts and retries. Compare cold novel requests, exact repeats, paraphrases and source updates separately, plus a predeclared representative workload mix. Use repeated stochastic trials and paired confidence intervals. Charge all attempts, including failures, to total cost divided by independently correct complete answers. Report coverage and precision alongside cost so declining questions cannot manufacture savings.

Proposed savings gate: against the least-cost baseline meeting the same correctness/coverage gate, aim for at least 30% lower measured API cost per correct complete answer on the predeclared workload, with a paired 95% confidence interval excluding zero savings; accuracy noninferiority margin 2 percentage points, with enough independent cases to resolve it. Report latency and total-cost sensitivity separately. If the study is too small or the advantage is absent, report inconclusive/no demonstrated advantage and improve routing; do not change the baseline or thresholds after seeing results. No numerical advantage is promised by this plan.
