# Native-feed diagnosis, group g2 (DQ, REV, HOS, CLN) - 21 questions

Method: read-only. Derivations come from `landing.sqlite` (and, for DQ, the public release `raw/manifest.json`, which is
the delivery manifest: path, sender, format, claimed records, delivered date, bytes, sha256). Semantic-layer checks come
from `semantic.sqlite3` plus `analyst_docs`. No answer keys were opened; "derived" below means the literal reading of the
definition, not a graded truth. Persons = `stg_person_map` clusters (Agere AGP ids).

Facts that matter across questions
- Every landing table is mirrored 1:1 as `raw_*` in the semantic layer (row counts equal for all 152 tables).
- NOT in the semantic layer: `ingest_files` (file-level delivery rows) and `raw/manifest.json` (delivered date, sha256,
  claimed record count). `ingest_files` itself has only relpath, bytes, mtime (= copy time, not delivery), parsed rows,
  parser, error. It cannot answer lateness or content identity.
- `payer_claim.first_status` is wrong for 15,468 of 178,734 claims (8.7%): it equals `final_status`, not the status of the
  sequence-1 adjudication (e.g. 7,240 claims first `denied`, shown `paid`). `payer_claim.adjudications` is 1 where the
  claim has more (17,649 claims). `payer_adjudication` is correct.
- `payer_claim.network_status` is null for every claim of payers 0, 1, 2, MSSP, SUP1, SUP2 (no NETWORK field is
  delivered for them; only the 10 flat payers carry it).
- Analyst conventions in `catalog_index.md` ("Money is integer USD cents", "documented diagnosis is any condition row",
  "deduplicate patients") and the `counts_in_metrics` / `superseded` / `version_status` flags are warehouse conventions that
  the native definitions do not mention; they generate alternative "readings" and drive the clarify answers.

## CLN-04 BP without hypertension code (Agere 232 / 232)
- Derived (semantic, literal): persons with >=2 readings SBP>=140 or DBP>=90 = 838; minus any I10-I16 on problem list,
  encounter dx, or paid payer-claim dx = **232**. Variants (condition table, claims all statuses, claims paid only) all 232.
- Native cross-check: BP readings are present for Epic flowsheet 17,022 (semantic 16,317 after dedupe), athena 1,272,
  eCW, FHIR; every native HTN-documented person (Epic problem list/enc dx, athena problem list, FHIR Condition, flat claim
  dx) is in the semantic exclusion set. No duplicate-reading inflation (838 either way).
- Class **D**. Agere's number equals the literal derivation, so the content is not the likely fault. Leading hypothesis
  (also CLN-06, CLN-14 not applicable): the answer is a patient set and Agere returns `AGP-...` ids; NATIVE_IDS.md says
  ids must be native forms (`epic:<inst>:<pat_id>`, `mrn:`, `member:` ...) and unresolvable ids count as wrong patients.
  `patient` has no native key column; keys exist only in `raw_stg_person_map`.
- General fix: see Fix 2 (native-id rendering of patient sets).

## HOS-14 Stays 2029 with LOS > 7 (Agere 49 / 49)

  `counts_in_metrics` filter is not in the definition.
- General fix: Fix 3 (stay builder: inpatient discharge = discharge else statement-through; document).

## REV-15 Plan pharmacy paid 2028 (Agere 3,322,122.92 / same)
- Semantic reproduces 3,322,122.92 = paid 3,326,282.11 plus 18 recoupment rows -4,159.19.
- Defect (A): the layer keeps ONE row per Rx claim id = the final event. A recouped claim becomes a single row with
  `fill_date` = recoupment date and plan_paid = the negative; the original paid fill (+9.22 on 2027-10-23) is gone, and
  `reversal_of_record_id` is null. "Paid fills minus recoupments" for fills in 2028 nets recouped fills to zero, so the

- Class **A**. Also 820 Part D (`CCLF-PDE`) rows carry null plan_paid (CCLF7 has none), harmless here.
- General fix: Fix 3 (claim-event model: keep paid and reversal events, link by claim id, original fill date on both).

## Top 3 general fixes

1. Expose delivery metadata (DQ-01, DQ-02, DQ-03, DQ-04, DQ-05; helps DQ-13/14). Ingest `raw/manifest.json` as a
   `delivery_file` table (path, feed, sender, format, claimed_records, delivered, bytes, sha256), join it to `ingest_files`
   and the three `*_parse_issue` tables, and add derived columns: variant (resend/v2/restatement), nominal_cycle_date and
   `delivered_lag_days`, parsed_rows vs claimed_records, `content_identical_to` (sha256 group), `empty_where_expected`,
   `truncated`, series gaps by feed. Add the table and its columns to `analyst_docs` with a short "file-level questions"
   section. Replace `ingest_files.mtime` or label it copy time.
2. Surface identity and chart structure, and render patient sets natively (DQ-08, DQ-13, DQ-14; CLN-04, CLN-06 if the id
   hypothesis holds). Add a `person_source_key` / `patient_chart` view (person, system, instance, native key, tier, evidence,
   flags `same_instance_duplicate`, `migration_pair`, first/last drop) and document it. Make the answer layer convert AGP
   ids to one native identifier per person (`epic:`/`athena:`/`ecw:`/`mrn:`/`member:`) as NATIVE_IDS.md requires. Add a
   modeled `death` fact (CLN-14).
3. Fix claim-layer semantics and analyst conventions (REV-02, 06, 10, 12, 13, 15; HOS-10, 14; CLN-06). (a) Rebuild
   `payer_claim.first_status` and `adjudications` from `payer_adjudication`; keep reversal and recoupment events in pharmacy
   with the original fill date; inpatient discharge = discharge else statement-through; fill concept and canonical value for
   unmapped labs (eGFR). (b) Docs: state grain rules (event questions use `payer_adjudication`, claim questions
   `payer_claim`), map native terms to exactly one column (`product` vs `line_of_business`), note which columns are null
   because a payer never delivers them (network, discharge), and say the question's own definition wins over
   `counts_in_metrics`/`superseded` flags. (c) Prompt rules: commit to the literal reading with stated assumptions instead of
   returning `clarify`; default money to dollars; expand "REV-01"-style cross-references into the actual definition.
