# Native-feed diagnosis, group G1 (RWE + RX, 21 questions)

Workspace: `artifacts/workspaces/pilot-native-v2-12` (landing.sqlite = delivered files parsed; semantic.sqlite3 = what Agere analysts query).
Method: each question derived literally from landing tables (persons = `stg_person_map` clusters, as_of 2030-05-27), then re-derived from the semantic layer, then both compared with Agere's two answers. No answer keys opened (nothing under `private/`). Read-only; no paid APIs.

## 0. What the data comparison established (read this first)

**Pharmacy fills: the semantic layer is faithful to the landing files, with one exception.**
Independent fill set from landing (NCPDP D.0 B1/B2 + payer flat pharmacy, latest version per claim id, any B2 / `reversed` / `recouped` event removes the claim, person via `stg_person_map`) vs `payer_pharmacy_claim` where `counts_as_fill=1`:

- Same claim ids, same person, same fill date, same days_supply, same NDC for every claim (82,839 landing fills vs 82,842 semantic; the 3 extra are short/truncated rows with null NDC and null days_supply, carried as "paid" with no drug).
- Reversal handling, `-R` resubmissions, RESEND/_v2 duplicate files, flat-only claims (C1 2027-12 and 2030-04, MA3 2027-12 where the NCPDP file never arrived), non-ISO flat dates (`MMDDYYYY`, `MM/DD/YYYY`, `MMDD-CC-YY`): all reproduce.
- Person map: 2,087 persons with NCPDP claims, zero DOB/gender conflicts inside a cluster; the same check on 837 subscriber DOB/last name and Epic patient DOB finds no over-merge; only 4 under-merged `ehr_only` clusters (typo variants such as Eli/Elijah Adams, Roy Wilson/Roy Wlsoni), none with pharmacy claims.
- Drug class: the semantic `fill.class_key` equals a name-keyword classification (RX-10 keyword list, applied to the NDC's drug name) for every chronic class used in these questions (only OUD agents differ: semantic puts buprenorphine/naloxone in `opioid`+`opioid_antagonist`).

**The one defect (A1): 162 duplicate Medicare Part D rows.** `payer_pharmacy_claim` holds 167 `CCLF-PDE-*` rows (162 paid). All 162 are the same fill as an existing MSSP NCPDP claim (same person, date, NDC, Rx number, fill number). Cause: 5 MSSP NCPDP cardholder ids are 12 characters (MBI plus a trailing digit, e.g. `8QCA20817D15` vs MBI `8QCA20817D1`, 7 MBIs involved), so the CCLF7-vs-NCPDP dedupe key (MBI + Rx + fill) misses them. 41 of the 162 fall in 2028, so 2028 paid fills = 21,888 in Agere vs 21,847 true.

**Other defects found while testing the non-pharmacy items:**

- (A2) FHIR bulk practice-instance resources are not carried. `fhir_bulk/<practice>` (not DEEPCHART) DocumentReference rows: 4,257 landing rows, only the `ehr/fhir/<practice>` 488 reach the semantic layer (lineage: 976 of 68,359 DocumentReference refs; MedicationRequest 1,470 of 23,612; Condition 289 of 9,364, Encounter 1,022 of 99,564, Appointment, Immunization, Allergy similar). Deep-chart bulk is duplicated by Epic on purpose, practice bulk is not.
- (A3) Problem-list date is on the onset clock. `problem_list_entry.first_recorded` and `condition.event_date` carry the eCW `onsetdate` (e.g. 2027-02-28) while the entry was added/documented on a later `addeddate` (2027-10-08, kept in `record.recorded_date`).
- (A4) `note_therapy_change.drug_key` is not the first word of the drug (`amphetamine aspartate`, `metformin with curr...`).

Everything else Agere answered matches my literal landing derivation exactly (see table). For those I could not find any data-level cause; classification D unless noted.

## 1. Per-question results

Notation: "true" = my literal landing derivation; "sem" = semantic-layer derivation an analyst would run. Persons are Agere clusters.

### RX-01 statin persons 2028
- Landing: paid, non-reversed fills with fill date in 2028, statin class by name; distinct persons = **497**. Variants (ncpdp-only, +PDE dupes) = 497; "no MSSP" = 386; including reversed claims = 499.
- Sem: `fill` (class_key='statin') or `payer_pharmacy_claim` + drug_name; 497. Expressible faithfully.
- Agere 497/497 = true. **Cause D** (no data defect; if the key differs look at person universe 4,095 clusters vs 4,113 manifest patients, or the RxNorm catalog class vs name class).
- Fix: see G (identity audit).

### RX-02 mean statin PDC 2028
- Landing: persons with >=2 statin fills dated 2028 = 458; days covered = carry-forward-shifted supply from first 2028 fill to Dec 31 (truncated at 12/31, no 2027 carry-in); denominator = days first fill..Dec 31 inclusive. **Mean = 75.3238** (no PDE dupes). Union (no shifting) = 75.0028.
- Sem: same with `counts_as_fill` fills: 75.4060 (shifted), which is Agere run A exactly. The 0.08 gap is the 41 duplicated PDE fills.
- Agere A 75.406 (A1: PDE duplicates) and B "clarify" (listing shifted vs union vs carry-in readings). **Cause A (A1) plus B** ("best course" is under-specified: standard PDC shifts overlaps; docs give no PDC convention).
- Fix: dedupe PDE (fix 1); add a documented PDC convention (shifted, truncated at period end, no carry-in) to analyst docs.

### RX-03 prescriptions picked up 2028
- Landing 21,847 paid non-reversed claims dated 2028. Sem `counts_as_fill=1` and fill_date in 2028 = 21,888 (21,847 + 41 PDE duplicates). Agere 21,888 both runs. **Cause A (A1).**

### RX-05 top 5 classes 2029 (persons)
- Landing/sem: statin 476, arb 227, ssri 221, ace_inhibitor 213, calcium_channel_blocker 181 (6th penicillin 172, 7th thiazide 169). Agere identical in both runs. **Cause D.** Note a multi-class combo claim counts in each class (as the rule "combination counts toward the named ingredient" implies for chronic lists); the `fill` table has 85,954 rows for 83,004 claims for this reason, so never count claims from `fill`.

### RX-07 ACE to ARB switch
- Landing: first-ever ARB fill D; some ACE fill in the 90 days before D; no ACE fill after D; through as_of = **13** (strict/inclusive on D both 13). Agere 13/13. **Cause D.**

### RX-08 GLP-1 members 2029
- Landing 57 persons; sem 57; Agere 57/57. **Cause D.**

### RX-09 note-only stops
- Landing: regex `Stop <drug> due to <reason>; (patient|pt) instructed to discontinue` over Epic `hno_note_text` (reassembled by note_id+line), FHIR DocumentReference `text` (all versions), athena `documenttextdata`; drug = first word lowercased; pairs (person, drug); deep-chart persons excluded (none have the template; all stops are practice notes) = **55 pairs** (Epic 20, athena 12, FHIR 60 rows from 54 mapped; some pairs repeat across feeds).
- Sem: `note_therapy_change` action='stop' = 40 distinct (person, drug_key); 18 landing pairs have no semantic row: 17 from `fhir_bulk/<practice>` DocumentReference rows never loaded (A2), 2 from key formatting (`amphetamine aspartate`, `{28...`: A4); 3 semantic keys are not first-word.
- Agere 38/38. **Cause A (A2 mainly, A4).** Needs file/segment-level facts only in the sense of the missing feed: `raw_fhir_documentreference` in the semantic layer would answer it (landing has the text), C is the fallback if raw_ tables lack the practice-bulk rows.
- Fix: load practice-instance `fhir_bulk` for every FHIR resource (fix 2); normalise `drug_key` in the extractor to the ingredient first word.

### RX-10 restarts after >90-day gap (chronic classes)
- Landing: classes by name keyword list given in the definition (combos to named ingredient; sacubitril/valsartan = ARNI only), gap = next fill date - (fill date + days_supply) > 90 between consecutive fills of the class, through as_of = **493** (same with PDE dupes). Agere 493/493. **Cause D.**

### RX-12 generic share of 2028 fills

## 3. General fixes

1. **Cross-feed duplicate keys must be normalised, and the semantic builder must assert uniqueness (staging adapter + semantic builder).** Dedupe CCLF7 PDE against MSSP NCPDP on a normalised identity (MBI prefix of 11 characters, strip person-code suffix) plus (rx number, fill number, NDC, date), and add a builder invariant: at most one `counts_as_fill=1` row per (person, ndc, fill_date, rx_number, fill_number) with an alert when two sources collide. Same pattern for any "A also in B" merge. Addresses RX-02, RX-03, RX-11 (and removes the doubt behind every other pharmacy item).
2. **Load every delivered clinical feed instance, with a coverage report (staging adapters).** Treat `fhir_bulk/<practice>` exactly like `ehr/fhir/<practice>` (all DocumentReference, MedicationRequest, Condition, Encounter, Observation resources) and publish landing-to-semantic row coverage per table (lineage already allows this; many tables show 0 or <5% coverage with no explanation). Normalise note-extractor outputs to canonical keys (first-word ingredient). Addresses RX-09 and any note/medication/condition item that depends on FHIR practice data.
3. **Date-clock and definition conventions in the analyst docs (semantic builder + docs).** (a) Every date-bearing table exposes both clocks as named columns (`onset_date`, `documented_date`/`recorded_date`, `service_date`, `paid_date`, `available_date`) and the docs state that "documented / first documented / recorded" means the documentation clock (fixes RWE-10). (b) Add a conventions page for repeated rules: PDC (carry-forward shifted, truncated at period end), "more than N days" is strict `>`, "after"/"within N days after" excludes the same day unless stated, "as Q-xx" cross-references reuse that definition verbatim including windows, new-user and restart semantics (FIRST fill, course vs all-time). Addresses RWE-05, RWE-07, RWE-08, RX-02 and hardens RWE-01/02/04.

Also worth a decision (not a fix here): RX-12 needs a drug-catalog reference table (NDC to generic/brand/tier) or an explicit "native feeds carry no formulary tier" statement in the docs so the question is answered "unsupported" deterministically (C).

## 4. Method notes and caveats

- All numbers above were computed with a throwaway harness (scratch directory, not in the repo) over `landing.sqlite` (read-only) and `semantic.sqlite3`.
- "True" values assume gold = literal reading of the definition on delivered files. Where the gold could differ (class catalog via RxNorm instead of drug name, 4,113 manifest patients vs 4,095 Agere clusters) I could not test it; the identity checks above found no over-merge in the pharmacy population.
- Semantic lineage coverage (`record.payload._lineage`) was used to find unloaded landing rows; a table with 0 coverage is not necessarily a defect (look-up and code tables), but `fhir_*`, `ehr_epic_pat_enc_dx`, `ehr_athena_clinicalencounterdiagnosis`, `ehr_ecw_diagnosis` show 0 or tiny coverage and deserve an explicit check.
