# Native diagnosis g4 (VBC + ACC, 14 questions), workspace pilot-native-v2-12, as_of 2030-05-27

Method: independent derivation from landing.sqlite (stg_person_map persons) versus what an analyst can express from semantic.sqlite3 + analyst_docs. No answer keys were opened. "Literal" numbers below are my derivations, not keys. Scripts are in the session scratchpad.

## Cross-cutting findings (measured)

1. Pre-reissue spans are missing from semantic.enrollment_span. 64 member_ids exist in x12_834_member / payers_eligibility but not in enrollment_span (53 resolve to a person via stg_person_map, 11 do not). Example: member C1D3919E98C (834 021 add 2026-09-01; flat eligibility term 2027-06-14) has no row, so person AGP-03b0cb28d588 appears to start on 2027-06-15 (the member_id_reissued continuation C1187A6BA38F). The definitions say a span superseded only by a reissue is KEPT. Missing months in 2028: commercial 91, marketplace 35, medicaid 12, dual_ma 5.
2. Medicare FFS and dual FFS spans have attribution_npi (a group NPI) but attribution_practice_id NULL: 264 spans (218 medicare_ffs, 46 dual_ffs), 211 of them active at as_of. Every one of those group NPIs maps to a practice through rosters_aco_provider_roster.group_npi. All other products have the practice filled.
3. member_month is documented as "covered on ANY day of the month" and carries one product per person-month (latest start wins). The definitions use "covered on the 1st", through death, once per person per month per product. The doc is silent on both mismatches.
4. No death table. The only real delivered deaths are CCLF8 bene_death_dt: 45 MBIs, 44 persons, all medicare_ffs (38) or dual_ffs (6). stg_person_map keys MBIs as `mbi:<MBI>` (not `member:`), which is where run B of VBC-12 gave up ("none link to any person"). Epic/eCW death_date columns hold shifted-column junk (address text, "APT 2").
5. Semantic claims layer is sound. Flat payers_medical latest-event vs payer_claim: 25,290 vs 25,303 paid 2028 claims, $6.620M vs $6.628M; the gap is later 835 adjudications the flat files do not carry. So claim-driven questions are not suffering a data gap.
6. Appointment layer drops delivered scheduling records. semantic.appointment = Epic f_sched_appt (28,819) + eCW 753 + FHIR 579 (only the 4 FHIR-native practices). Landing has 32,273 distinct FHIR Appointment ids: 27,179 DEEPCHART (a 1:1 re-expression of the Epic deep-chart appointments under different ids, so collapse is right) and 5,094 from practice folders. 2,799 of those 5,094 duplicate an Epic/eCW appointment (same person and day); 1,716 do not. Athena has no appointment table, so for athena practices the FHIR resource is the only scheduling record. Those 1,716 are absent (485 with 2028 slot, 418 with 2029 slot).
7. Slot date and booking date. 479 deep-chart appointments have NULL scheduled_date (no slot_start; the delivered "date" is the made/created timestamp). Semantic booked_date is NULL for 47% of appointments because it is taken only from a "booked" version, but appt_made_dttm is present on 40,179 of 40,183 deep-chart rows and on every Epic version. So lead_time_days is NULL for about 14,200 Epic appointments.
8. eCW: semantic keeps deleteFlag=1 retired slots (551, status fulfilled) and no_show/cancelled/booked rows, and drops the 2,544 CHK deleteFlag=0 rows. Plausible (those are the visit rows), but the definition's "each EHR's appointment table" does not say so.

## Per question

### VBC-01 members attributed per practice
1. Literal: persons alive with an active primary span at 2030-05-27 (excluding medigap/COB; latest start when two active), practice from the span's attribution (roster group_npi for FFS). 2,044 members across 126 practices; 102 practices differ from Agere. Agere's 1,833 (both runs, identical) = semantic only. No active attributed person is dead, so death is irrelevant here.
2. Semantic: enrollment_span.attribution_practice_id is NULL for 211 active FFS/dual FFS spans; an analyst reading the docs sees "payer attribution (attribution_practice_id/attribution_npi)" and has no hint the practice is missing for Medicare. Faithful only after mapping attribution_npi to practice through the roster.
3. Cause A: mapping, group NPI to practice for medicare_ffs/dual_ffs (211 members, 10.3%).
4. General fix: resolve every attribution (NPI/TIN/group NPI) to practice during adaptation with a roster join, and add a docs line "practice null means unattributed, not unresolved"; add a post-ingest check that no span has npi set and practice NULL.

## Top 3 general fixes

1. Lossless, convention-explicit enrollment layer (VBC-01, 02, 07, 11, 12): keep reissue predecessor spans, resolve FFS attribution through the roster (group_npi), provide a person-month-product view (covered on the 1st, through death), and give a `product` vs `line_of_business` rule in docs and metric registry.
2. One appointment entity over every delivered scheduling feed (ACC-01, 04, 05, 10, 11): add FHIR Appointment resources for non-FHIR-native practices with a documented cross-feed dedupe key, fill booked_date from any version's made/created date, and apply the slot-date fallback chain (slot, scheduled, date, made/created) so no appointment has a NULL slot.
3. Missing entities and references (VBC-08, 11, 12, 14, ACC-07): add person_death (CCLF8 plus repaired EHR deaths, with the `mbi:` key note), the public ICD-10 to HCC V28 reference table, a roster affiliation history including implicit moves, and AWV lines from CCLF Part B; and brief the analyst to answer with the defined reading instead of returning clarify when the definition is explicit.

Open items I could not settle: 11 predecessor member ids do not resolve to a person in stg_person_map (spans not restored, so VBC-02/07 literal figures are slightly low); the cross-feed dedupe key for Epic-deep vs FHIR-deep appointments (I collapsed them); whether the key counts eCW CHK visit rows as appointments (semantic does not).
