## User-visible change

The shared investigator can discover, inspect and execute the existing analytical
engines with typed parameters. Its tools use the existing graph validator and
executor, exact inherited or explicitly narrowed patient membership and the received
snapshot. The resulting complete tables become SQL result views and can bind the
final answer and existing deliverable workflow. Empty membership stays empty;
foreign patients and date/source changes are rejected. This adds no disease handler
or alternative clinical architecture.

There are 60 advertised analytical choices and 61 typed read-only operators
(including the native aggregate operator). The catalogue includes trajectory,
survival, queueing, causal/program analysis, allocation, network analysis, payment
integrity, risk, policy search and outreach learning. Stateful care dispatch and
identity decisions keep their existing explicit workflows.

These are implementations of existing methods, not new scientific results:
trajectory analysis reuses uncertainty-aware segmentation and Theil–Sen slopes;
queueing reuses Erlang models and capacity calculations; outreach learning reuses
Beta–Bernoulli posteriors and Thompson allocation. Cross-industry origins, including
astronomical change-point methods, do not establish healthcare suitability. Every
result retains its native method, assumptions and limitations. A mathematical
estimate cannot replace missing observed clinical evidence.

The received-source check found an existing trajectory default that flagged 144
patients but returned only 50. Omitted `top` now returns all 144; an explicitly
requested limit remains supported. Other engines retain their native parameter
contracts and disclosed limits; this is not qualification of every engine.

## Connected recursive learning

The new isolated `component-learning/components.sqlite3` records immutable model,
event and observation history. In `AGERE_COMPONENT_LEARNING=on` mode the answer
hooks bypass the old learning/question-plan/answer-store capture paths. No benchmark
or protected source is discovered. Evaluation mode records and trains nothing.

The loop is now connected:

1. Complete execution records an observation. Native success may supervise which
   existing tier could execute a task; it is explicitly machine supervision.
2. Direct client review can supply acceptable routing/shape labels and a source
   family. Model-generated learning requests cannot impersonate user approval.
3. An explicit learning plan exports only eligible new observations. Families are
   assigned once by an explicit mapping or a stable salted hash before inspecting
   labels. Fit, calibration and verification families, patients and wording remain
   separate. The loop waits when those requirements are not met.
4. Existing logistic fitting compares classical lexical features, the pinned stack
   encoder and any explicitly supplied pinned encoder. Calibration sets confidence
   thresholds; verification does not fit them. Selection favors acceptability,
   fewer confidently wrong decisions, reliable coverage, then avoiding an encoder.
5. A candidate records data hashes, provenance, source/trainer identities,
   comparisons and parent revision. A plan must explicitly authorize installation;
   otherwise it remains a candidate. The ordinary router, tier ordering and answer
   shape hint consume released heads through their existing paths. Native answer
   and evidence checks remain required; tier ordering never removes available tiers.
6. Correction quarantines the release and related fixed-weight RSI reuse. It also
   removes superseded training labels. Unchanged rejected supervision cannot simply
   retrain and reactivate the rejected head. New reviewed data can drive another
   measured revision; prior selected revisions remain available for explicit rollback.

An in-process nonblocking lock prevents competing training jobs. Bookkeeping or
optional model failures do not fail a valid answer. There is no new background
service, provider retry, fixed patient cap or training row threshold substituted for
the required family separation. Local training costs time and compute; zero provider
calls does not mean zero operating cost.

`config/agere/learning/offline-candidates.json` is the executable candidate plan.
Router and shape supervision require direct review. Complete native executions may
supply explicitly labeled tier-routing supervision. At this checkpoint all three jobs had
`install: false`. The later SLM extension adds four adapter jobs; all seven remain
`install: false`. Set `AGERE_COMPONENT_LEARNING_PLAN` to an explicit plan only in
the intended isolated runtime; the default runtime is unchanged. With no plan,
the hook records observations only. The CLI `tools/training/self_improve.py` also
accepts an explicit approved manifest and never defaults to old benchmark stores.

Fixed-weight execution RSI from the preceding increment remains separate: it
qualifies a native tool sequence, checks source/scope/definition identities, replays
native tools and requires a fresh final evidence review. Component releases that
change execution invalidate that reuse. Training comparisons and execution-reuse
savings are separately attributed; no total-cost improvement is claimed yet.

Local receipts are in `artifacts/agere-components-learning-2026-10-26/`:

- `tests.json` and `tests.log`: 451 passing checks and four optional/unavailable-data skips,
  zero provider calls or blocked send attempts. Guarded regressions include complete authored
  note/dose/deliverable execution and automatic feedback → fit → release → correction
  → refit → rollback behavior. Scripted model judgments are engineering fixtures.
- `received-verification.json`: trajectory and queueing executed through the new
  tool on all 4,115 received patients. Trajectory returned all 144 flagged rows;
  queueing returned 168 hour-of-week rows. These counts are not clinical grades.
- `authored-routing.jsonl` and `routing-manifest.json`: 24 newly authored task-role
  questions across three roles and nine disjoint families: 12 fit, six calibration,
  six verification. They contain routing labels, not healthcare answer keys.
- Three-way local comparison: classical, MiniLM and UltraBERT each chose acceptable
  roles on six verification cases. Classical/MiniLM cleared their calibrated gates
  on five; UltraBERT cleared its gate on six. The selected UltraBERT head loaded its
  own pinned encoder without a supplied stack encoder and served all six through
  the runtime registry. That separate compatibility-test release was then retired.
  This small experiment establishes wiring, not general superiority or clinical accuracy.
- Model histories, full native engine receipts, verification scripts, frozen source
  and the retained-ledger resume command remain local, outside GitHub source export.
