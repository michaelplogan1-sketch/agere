## 1. Decision: the architecture is final

Keep it as built. No new layers, routes or rewrites.

- **Deterministic engines and governed metrics compute.** These are 67 versioned metric definitions plus the decision context, which
  holds Mike's definitions (including the four decided 2026-10-25).
- **System One (Jev, then Perplexity) reads and judges closed questions** per whole document, and checks whether an answer fits the
  question.
- **Haiku interprets cheaply.** It writes the spec, and a compiler executes it.
- **Sonnet investigates what the free layers do not settle.** It works with tools: governed metrics, SQL, documents, the Jev document
  judge, the conversation and the saved cohort.
- **Opus is deliverables only.**

From here, changes are specific fixes to measured failures, small and tested, one at a time.

## 3. Is the warehouse the problem? Partly, in specific and now-named ways

**What is not wrong:**
- The received source is structurally sound (Codex's metadata audit):
  - 4,115 patients and 2.4M records;
  - 0 orphan references, 0 invalid JSON, 0 malformed dates, 0 records received after the cutoff.
- The six diagnostic references were re-derived independently from raw rows and match.

**What does cost points:**
1. **Undeclared definitions in the answer keys** were the largest cause on population and insight questions. Analysts can reasonably
   disagree about each of these:
   - observation counted as a stay or not;
   - living-only or all patients for event counts;
   - net vs gross pharmacy spend;
   - which visits count as follow-up.

   Mike decided four of them on 10-25. Keys v2 apply them; v1 is kept.
2. **Counting grain and visibility.** The semantic layer keeps current claim versions in `record` and `payer_claim`, and every
   adjudication in `payer_adjudication`. A question about "received rows" answered from the wrong table is off by the superseded
   rows (82 vs 77 in the diagnostic). This is a documentation gap in what each table holds, not corrupt data.
3. **Strict scoring.** A right answer quoted from a sibling record of the same visit scored wrong (2 of 4 notes misses examined on
   10-26). Scorer v2 removed three false passes. It does not yet accept equivalent evidence from another record of the same
   encounter.
4. **Synthetic-source flags** (Codex's temporal audit): 49 records dated before the patient's recorded birth, and 2 future event dates.
   These are review flags, not proven root causes, and no generator change is authorized.

**Qualifications, kept as Codex required:**
- Metadata checks do not rule out a broken semantic adapter, clinical inconsistency or a wrong reference.
- A quote's provenance does not show that the headline follows from it.
- The diagnostic packet is controlled, not a clinical-realism benchmark.
- Synthetic-only evidence supports synthetic-benchmark claims only.

**What is the stack's own fault (fixed or open):**
- **Fixed 10-25 / 10-26, all tested, 0 new regression failures:**
  - retrieval output and pattern readers had the last word on notes;
  - a nested budget leak;
  - a saved cohort turned the LLM off;
  - quote provenance and negation flips;
  - unscoped and uncached document reads;
  - backstop answers skipping the answer gate;
  - the subscription tool-call format (x1-25).
- **Open:**
  - insight completeness (23 % with half the facts present);
  - full-stack latency on one-patient notes (~2 min against ~20 s for the investigator alone, same answer);
  - a model still miscounts when it is handed raw rows instead of computing them.

## 4. What happens next (bounded, in order)

1. Codex adjudicates the six diagnostic cases independently. Then two specific fixes, if confirmed:
   - **(a)** table documentation: `record` holds current versions; `payer_adjudication` holds every adjudication;
   - **(b)** one-patient note questions go to the investigator first, so they don't wait ~100 s on earlier tiers.
2. Each fix is measured with `--quick 3` (15 questions, about 10 minutes) on BUILD or open cases. No more full reruns per change.
3. **One milestone:** freeze candidate, definitions, scorer and transport. Run the check half (labelled reused validation) and held-out
   once, on the subscription, with the outage stop.
4. **A defensible accuracy claim needs a fresh, independently authored test set with a separate adjudicator.** Neither dev3 nor
   held-out qualifies any more. The same applies to a 95 % claim: it needs a predeclared sample size, which a small perfect packet
   cannot provide.
