4. **Best path to generalize**

   **Without Anthropic credits:** finish one typed expression tree shared by charts, populations, claims, and note predicates. Bind literal numbers and dates deterministically; use System One for bounded operator/concept/assertion choices. SQL should handle structured facts, joins, clocks, arithmetic, and denominators. Evidence reduction must preserve unknowns, retrieval incompleteness, and unresolved anchors. Apply one acceptance policy to every route.

   Develop through independently authored composition cases: change AND↔OR, thresholds, rank direction, missing evidence, date anchors, and saved populations. Compare exact memberships and numerator/denominator sets. Keep expensive overlapping proposers as experiments until they demonstrate incremental value. System One remains separate provider spend; this approach is not necessarily $0.

   **With a small Haiku budget:** use one bounded call to produce the same spec after deterministic/System One interpretation remains unresolved, plus at most one repair from validator feedback. Supply only relevant schemas, definitions, and frame options. Verify each requested part; unresolved meaning prevents a definitive answer. Cache accepted specs under source, definition, and policy identities. Measure Haiku’s incremental correct coverage and cost per additional correct answer. The current model-policy wrapper only downgrades Opus requests; it does not implement this planning strategy.
