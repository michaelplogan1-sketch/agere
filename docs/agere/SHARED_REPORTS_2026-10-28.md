# Shared saved-answer reports and app accounting

The ordinary workspace now offers reusable report or custom model-generated design. The reusable path renders the exact server-saved answer, full result rows, sources, unknowns and declared workflow into searchable, printable HTML. It adds no analytical interpretation, model request, clinical acceptance or service execution. Browser printing supports PDF output; this change does not add a server PDF engine. Custom frontier composition remains available explicitly. Existing API clients retain their generation behavior unless they select `delivery_generation=saved_report`.

Report generation is bound into the saved workflow identity. Its source/dependency checks run before and immediately before saving. Partial findings remain partial. Compound financial and nonpatient outputs remain complete; no patient cohort is inferred from an aggregate result. HTML and script delimiters in source text are escaped, and template markers are replaced in a single pass.

Shared interpretation checks now detect widening one registered medication subtype in a contributing CASE expression, including IN and OR forms. This extends the existing exact-group compiler check; it does not create a condition-specific answer handler. Repair feedback returns to the existing investigator. A historical answer is not silently marked corrected.

Request-wide usage replaces planner-only counts in the workspace and summary when available. Unknown telemetry does not fall back to a cheaper planner estimate. Pricing preserves cache TTL breakdowns, validates token counts, and supports published long-context tiers. Execution-time price versions remain distinct from later repricing and from invoices.

Isolated component-learning runtimes bypass legacy benchmark-dependent semantic/template caches before touching either corpus or legacy learning stores. Cached briefing cards must reopen current saved answers with matching question and source, or they are rebuilt by the existing offline checks.

Verification: 160 authored offline checks passed on one source identity, plus five request-cost UI scenarios. The first guarded selection denied six legitimate offline Node checks; those six were rerun with only Node syntax/assertion subprocesses permitted. The initial receipts are retained. No provider request or protected corpus content was used. Native response, stage accounting and analytical definition discrepancies remain local ignored evidence. This is an engineering increment; ordinary workflow and broader G3/product qualification remain open.
