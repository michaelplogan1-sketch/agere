# Portable synthetic source intake and mapping revisions

October 11, 2026. The Connected stack view now accepts a bounded synthetic source package, an explicit one-to-one patient crosswalk, source clocks and literal field mappings. It runs the existing warehouse snapshot, documentary-state and requirement evaluators, then saves the original input, evidence, results and unresolved mapping/evidence work. It never merges the intake with the active original-cohort warehouse.

The first executable scope maps renal laboratory results, nephrology attendance reports and reported affordability. Received/source/recorded dates stay separate; collection and attendance dates require explicit fields. Unknown clocks remain unknown. Unknown source categories, missing receipt dates and missing correction parents remain visible and do not enter analytic evidence. Identity collisions, unmapped patient IDs, invalid dates, private author fields, unsupported target fields and invalid value types reject. Source row hashes, raw source identifiers, canonical identifiers and field aliases are retained. All roster patients remain in the denominator, including those without visible records.

A second capability saves immutable mapping versions and compares their effects on the same original source hash, cutoff and documentary question. It shows both complete mappings, changed requirement states and preserved prior questions. A different source package cannot be presented as a mapping-only change. Historical code versions are labeled and cannot be compared as current. This is source-mapping review work; it neither dispatches care nor resolves clinical uncertainty by declaration.

## Actual demonstration

Two differently named synthetic column layouts run through the real HTTP intake route and produce the same documentary state/value results for all four patients. This is an engineered conformance example, not an independent EHR validation dataset or evidence of population generalization.

The source has 15 complete records. Thirteen are mapped; nine are visible at the selected cutoff. Exclusions distinguish one late arrival, one future source event, one superseded version and one quarantined correction. An unknown category and a missing receipt date remain outside the mapped analytic records. One patient has no visible records and remains in all results. One source event date is unknown.

The initial mapping omits the collection-date field. Adding the explicit `sample_day` mapping changes 12 requirement states across four patients. Three renal requirements for one patient become documented. Other states become accurately distinguishable as unobserved, conflicting or unknown semantics. Review work decreases from 22 to 19 items. All four patients still have unresolved clinical requirements; no eligibility or care recommendation is established. Reported affordability also preserves an explicit false account separately from true and unobserved accounts.

Four final reviews are current: the original and revised mapping, the alternate column layout and affordability. Seven development-era reviews remain immutable and labeled historical after validation-code changes. JSON numeric formatting exposed a comparison identity edge case; exact source hashes now prevent different encodings from being silently treated as an identical source package. No saved payload was rewritten.

## Verification and limits

58 focused checks pass, including 31 new intake checks and 27 existing clinical-state/source-interpretation checks. They exercise exact identity, complete denominators, clocks, corrections, missing mappings, typed values, hidden-field rejection, schema conformance, immutable replay, stale-code handling, tamper detection and exact-source comparison. The actual API verifies save/replay/reopen, source audit, both layouts, mapping revisions, affordability and cross-source rejection. The browser verifies entry, save, mapping edit, reopen, comparison and readable final results; no browser errors were observed. The nine visible record bindings match original source rows, field values, clock values and crosswalk entries. All 15 original rows remain in the saved package.

Broad preservation passes: all 130 previously protected files, 837 prior ledger rows, 380 work items/383 events, 11 capability tasks/33 events and 19 separate Documents research files remain intact. The final manifest adds three files, for 133 protected paths. The final new-file hashes were refreshed and rechecked after validation refinements; prior protected hashes were never changed. Active v1.23 still has 1,614 patients and 1,238,686 records, with no PORT intake identities merged into it. Existing source-meaning routing and all pending exact outbound permissions remain unchanged.

This version accepts at most 200 roster patients, 2,000 records and a 2 MB source package. It supports explicit date-only mappings, not a general timestamp/time-zone conversion system. It does not validate clinical terminology, source identity adjudication, mappings for every source category, narrative interpretation, production EHR/FHIR/MEDS conformance, tenant isolation or deployment readiness. A supplied mapping remains unreviewed; documentary requirements are internal development contracts. Full stack acceptance remains false.

No provider or token-count calls, no new API cost and no failed requests resent. Spending remains uncapped with accounting. The unchanged ledger has 824 validated/13 failed requests and a historical validated-request estimate of $7.513555524, excluding failed-response costs. The four previously rejected exact outbound packets remain pending; no new outbound permission was sought or bypassed.
