# Agere: bounded cross-source answers connected to program review

Delivered October 10, 2026. All patient evidence is synthetic. This is an implementation and integration receipt, not clinical qualification.

## Delivered behavior

The existing context builder, provider gateway and budget ledger now connect to a persistent cross-source interpretation. `case_synthesis.py` accepts only complete declared-scope context, verifies current same-patient received source hashes before and after inference, removes machine annotations from the provider evidence, and sends the original narrative and structured content with source clocks. The configured Claude route is used for open-ended synthesis; this does not claim Claude is empirically the best model for every task. Existing bounded Jev/Perplexity/Kev/d1 readers remain unchanged.

Every finding must cite bounded, exact, uniquely locating excerpts. Structured citations reference canonical structured-unit JSON; narrative citations retain original field offsets. Code rejects invented sources, invented excerpts, duplicate finding identities, malformed review references, truncated output and unexpected model revisions. These checks validate citation structure, not whether each sentence is entailed by its citations. Machine findings remain proposals. Hypotheses require unresolved discriminating evidence; conflicting-account findings require multiple evidence units. Unanswered questions and proposed source-review steps remain explicit.

Provider-native input counting precedes inference and is cached with the exact request. The input operating limit is 16,000 tokens, output reservation 4,000 tokens, and the existing 20,000-byte gateway request bound is retained. The shared ledger reserves inference expenditure and preserves failed attempts; no hard cap was raised. API reference used: [Anthropic count_tokens](https://platform.claude.com/docs/en/api/messages/count_tokens). Token counts and estimated prices are not invoice reconciliations.

The working interface supports source selection, bounded context assembly, inference, exact answer replay, expandable citations, source-graph inspection and a saved-answer URL. `synthesis_work.py` carries a hash-bound saved answer and its review questions into existing immutable program assessments. Program candidacy continues to come from the existing program rules. A source or answer change blocks reuse; materialization and subsequent operational changes recheck attached interpretation provenance. Preparation creates assessments/proposals only; no staff review, consent, work event, contact or clinical action was fabricated.

The active server launcher now loads the already-authorized existing provider credentials when `--allow-live-stack` is explicitly supplied. It does not print keys or add a new credential source. The current server session is **33118**, replacing 6133 / 79935. The application remains loopback-only at http://localhost:8885/stack.

## Live synthetic evidence

P-1001 question: what do received pharmacy renewal requests and prescriber responses document, and do they establish a medication regimen change? The declared scope has 8 units from two source categories. The actual request was 12,876 bytes. One live synthesis call produced 7 findings, 23 exact citations, 6 unanswered questions and 4 proposed evidence-review questions. A separate provider token-count request preceded inference. Provider count: 5,663 input tokens; returned inference usage: 5,659 input and 3,374 output tokens, about $0.090116 at the gateway's recorded pricing (not invoice verified). The inference response took about 29.84 seconds. See `live-verification.json` and `answer.json`.

The model distinguished expired-prescription renewal requests, reassessment responses and the lack of evidence establishing actual medication use or a regimen change. It also identified referenced request/original-response records outside the declared scope. These are unreviewed model interpretations, not clinician-adjudicated findings. Seven findings and 23 valid citations do not imply seven clinically correct conclusions.

An exact replay succeeded with live inference disabled. Actual local HTTP and browser routes then replayed the same answer, followed its citations into connected received sources, and prepared an existing heart-failure review assessment containing the answer. The existing program result remained one review candidate for this one selected synthetic patient; the model answer did not establish candidacy. Work-item/operational counts were unchanged. The saved assessment and proposal are in `work-assessment.json` and `work-proposal.json`.

26 focused synthesis/context tests and 14 work-bridge/existing program-work tests passed. Coverage includes incomplete scope, native token overflow, changed/added/deleted records, cross-patient evidence, disabled live dispatch and exhausted budgets, source races, invented/ambiguous citations, noncandidate preservation and stale attached answers. Browser verification covered seven rendered findings, source selection, exact cached inference replay, program assessment preparation, expandable citations, source navigation and no page overflow at 1440px/390px; no browser console errors were observed. This is integration evidence, not broad clinical validation.

## Limits and next work

- Four related source categories for P-1001 produced a complete context but a 27,327-byte synthesis request, exceeding the existing gateway bound. It was rejected before dispatch. The live case explicitly selected two categories; no claim of whole-chart interpretation is made. The next substantive build is to connect cross-source synthesis across existing bounded chart passes or a declared connected-record scope while retaining unresolved cross-pass dependencies and exact coverage. Do not silently drop sources to manufacture a complete answer.
- Source selection is explicit in the evidence drawer. General automatic task-scoping, plan-graph synthesis across populations and calibrated quality-aware routing remain incomplete.
- A model can cite real text and still misinterpret it. Entailment, clinical currentness, program applicability, causal effects and clinical accuracy are unqualified. Saved proposals do not automatically enter verified clinical state or train a model.
- Program assessment attachment is delivered; no real work item or external action was created. No human review was manufactured. Older assessments/history are preserved; changed implementation identity requires old prepared proposals to be rebuilt before materialization.
- The initial sandboxed network attempt failed before inference. The authorized network-enabled run succeeded. No model-result failure or new failed inference reservation occurred in this milestone.
- No warehouse migration, generator changes, frozen Kev/d1 experiment changes, reserved-cohort fitting, prediction promotion or new weights occurred. Active v1.23 remains the original synthetic roster. Full product acceptance remains incomplete.
