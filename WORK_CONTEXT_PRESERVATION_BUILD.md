# Saved-answer preservation during program refresh

Delivered October 10, 2026. Routine preparation and bulk refresh now retain existing machine-answer attachments, and explicit additions form a deduplicated union. Each inherited or added context still passes the original source/currentness verification. Nothing is promoted to clinical review, enrollment or authority.

The public work dispatcher adds this policy around the byte-preserved historical and functional engines. It reads only the selected program/patients' current assessments. Work-graph preparation identities now include relevant attachment dependencies so cached work proposals cannot hide newer attachments. A SQLite trigger protects the final write inside the existing transaction: an older or interleaved proposal cannot remove any attached answer. If one patient conflicts, the entire multi-patient save rolls back; the API returns a 409 conflict instructing fresh preparation. Existing assessments, answers and events remain immutable.

**Actual warehouse result:** a full 1,614-patient functional preparation retained the saved answer on SYN-69283717-971. Saving left all **256 work items and 257 events exactly unchanged**, including their serialized digests. Assessment `5278761a50013cbde1d7e9f5d123415b9bfb49314c520ab340a002a1c9a31ee3` still binds answer `4937dbd744271141f3ed99482cef4fce506c59eb3295096319c6841e524dd9fe`. An older full-population proposal without that attachment was rejected before losing any work. The program screen reports how many assessments contain saved answers and explains their retained, unreviewed status.

59 focused checks passed, including 13 new preservation tests covering bulk inheritance, explicit union, deduplication, patient/program isolation, stale inputs, interleaved saves, full-transaction rollback and direct-engine protection after guard installation. Python and workbench JavaScript syntax checks passed. The initial HTTP harness expected 400; the application correctly returned 409. The corrected harness completed and preserved its first failure log as evidence. No runtime failure or lost work occurred.

72 protected files, eight saved paid answers, both domain population receipts, four existing buyer tasks and the 19 external research Markdown files remain current. No provider or token-count request, model cost, source migration, generator/research modification or human review was added.

**Limits:** this policy preserves saved machine-answer attachments. It does not implement preservation/merging for every optional decision or financial context. If an attached answer becomes stale, verification blocks the dependent preparation; an explicit audited supersession/retirement workflow is still needed. The existing eight-answer context bound remains; attachments are never silently trimmed to fit it. No clinical conclusion is validated by attachment preservation. The selected-adapter registry and dedicated respiratory/behavioral population programs remain next substantive integration work.
