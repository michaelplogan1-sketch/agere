### prescription(record_id, patient_id, order_class, transmission, drug_name, rxcui, ordered_date, quantity, days_supply, refills_authorized, indication, ordering_clinician_id, pharmacy, organization_id, encounter_id, available_date, declared_fill_ids, fills_received, first_fill_date, last_fill_date, fill_expected, fill_status, filled, prescribed_not_filled, fill_basis, script_message_id, match_confidence, match_components, matched_chain)
One row per medication order (e-prescriptions with order_class e-prescribe, incident-diagnosis outpatient_prescription orders, legacy orders) with its fills. fills_received = matched paid, unreversed fills received by the snapshot: e-prescriptions by linked_fill_event_ids when the release declares them (v2.2); dispenses naming the order (medication_order_record_id); e-prescriptions without a link (v2.3: only the NCPDP SCRIPT message id) by fuzzy matching to a pharmacy prescription chain (patient + pharmacy NPI + Rx number) on drug (RxCUI via NDC, else ingredient + strength), prescriber NPI, days from order to first fill, new-prescription fill number, pharmacy and days supply: match_confidence (0-1, linked at >= 0.5), match_components (score per signal), matched_chain; other outpatient orders by the first same-patient, same-drug fill within 30 days. fill_expected = 1 for e-prescribe and outpatient_prescription orders. fill_status: filled | declared_unreceived (the order lists fill ids but no paid fill was received) | not_filled. prescribed_not_filled = 1 only for not_filled with fill_expected (NULL when unknown); for fuzzy-linked orders it means no chain matched with confidence >= 0.5 (cash fills and other pharmacies are not in the payer feed).
