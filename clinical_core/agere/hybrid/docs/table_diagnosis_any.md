### diagnosis_any(patient_id, icd10, source, source_detail, event_date, record_ref)
Every documented ICD-10 diagnosis, one row per source record: patient_id, icd10 (upper case, as received, dotted), source = condition (EHR condition records with is_diagnosis = 1, incl. EHR problem-list conditions, and, for diabetes and CKD only, laboratory-evidence rows; assessment topics, rule-outs and the laboratory-evidence rows of every other condition are not diagnoses) | payer_claim (payer_claim_diagnosis rows with counts_in_metrics = 1: current non-duplicate claim versions whatever their adjudication, so claims-only members count), source_detail = the source table / claim status, event_date (YYYY-MM-DD; claim service_from, condition date), record_ref = source record / claim id. This is the one condition-evidence rule every path uses (grammar, compiler, metrics, families), read by ICD-10 code. Encounter diagnoses are not part of it (encounter_diagnosis holds them). Use it to count or list patients with a diagnosis code: SELECT count(DISTINCT patient_id) FROM diagnosis_any WHERE icd10 LIKE 'F11%'. The same patient appears once per source record, so always count DISTINCT patient_id. condition alone holds only EHR condition records and undercounts documented diagnoses (payer claims add patients). By library concept (no codes) use concept_patient.
