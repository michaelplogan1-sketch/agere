# Financial questions to exact account evidence — October 10, 2026

An interpretation’s evidence question can now follow registered account links from the original answer sources. The app projects the received account records with the existing financial accounting engine, retaining integer-cent equations, selected snapshot provenance, payment inclusion/exclusion, unresolved timing, conflicts and source identities. It presents exact account evidence before offering the existing bounded interpretation path. Shared account identity does not establish semantic relevance, hardship, benefits or savings.

`need_accounts.py`, four API routes and `need_accounts.js` connect the question, account receipt and selected record context. Exact original-source anchors are required; unrelated accounts fail. Selected contexts contain every received record assigned to that account and the parents used by registered account inheritance. Overlarge scopes retain the existing context limits rather than silently dropping records. Source or original-question changes invalidate receipts. No need/review/task state is automatically resolved.
