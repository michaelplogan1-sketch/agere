# Agere whole-statement chart passes — October 9, 2026

Implemented in `clinical_core/agere/clinical/context_passes.py` and connected to
the [workbench](http://127.0.0.1:8885/stack). All records and examples are synthetic.

## New executable path

The `context_passes` graph operation reuses the shared source-context inputs and
partitions every mapped received source unit into bounded passes. It preserves
whole statements, exact source references, annotations, event/arrival/reference
dates, documentary prerequisites, opposing accounts and known source gaps.
Each unit appears exactly once in its task's pass set. There is no top-k exclusion
and no silent truncation. An indivisible unit that cannot fit is named explicitly
and blocks complete review. The code supports arbitrary declared source/concept
scopes; the three workbench examples demonstrate it across different questions.

Passes hold at most eight evidence units. Provenance is shared within each pass;
typed support choices refer to source units instead of repeating their contents.
Whole-population preparation is local. Specialist inference is a separate explicit
patient-scoped operation with a pass-call cap. Every provider request is checked
before the first paid call; source hashes and dependency versions are rechecked.

`/api/stack/pass-review` and `Stack.review_passes` connect prepared bundles to the
existing Jev/Perplexity gateway and shared ledger. The workbench offers Perplexity
review buttons. Source-linked proposals are reconciled across all passes:

- Missing support stays unknown, never a patient-level negative.
- Opposing proposals remain visible; no majority voting or probability averaging.
- Unsupported label/reference combinations become unknown.
- Partial review cannot appear complete. Validated individual calls replay from
  cache; progress is saved, and failed calls are not silently retried.
- Machine proposals do not automatically become clinical facts, eligibility or actions.

Endpoints: graph execution at `/api/stack/execute-plan`, bundle inspection at
`/api/stack/passes?id=...`, explicit review at `/api/stack/pass-review`.
Derived bundles live in population stack v3's `context-passes.sqlite3`; request
and review journals are in `pass-review-receipts/`. Existing single-packet context,
ranked review, source ledgers and frozen Kev/d1 experiments are preserved.

record nine Perplexity passes over **ECO-00171F43EAB5**, a synthetic chart previously

## Verification and limits

**46 focused checks passed** across `test_context_passes`, `test_task_context` and
`test_analysis_graph`. Coverage includes exact-once packing, oversize units,
cross-patient/pass references, opposing proposals, partial review, preflight caps,
typed response validation and cached gateway replay. Generated workbench JavaScript
passed `node --check`; browser execution showed the full medication population and
new pass inspection/review controls. The maximum ASCII-length planner request is
19,638 bytes, inside its unchanged 20,000-byte bound.

The new typed route consumes shared context, but existing ranked-review routes
remain available. Local Kev/d1 are not promoted by this build. No new weights were
trained. Complete packing does not establish cross-pass coreference, semantic
accuracy, clinical currentness or appropriate care. Whole indivisible units larger
than the configured budget remain an explicit general limitation, even though none
occurred in these three snapshot runs.

Multiple passes can increase tokens and repeated context. This build demonstrates
bounded full-evidence processing and measured specialist usage, not universal token
reduction. Do not infer full-population inference cost from two selected examples.
The default compiler, deterministic operators, cached results and selective model
routes remain essential; preparation does not trigger population-wide paid review.

Next: shared relation/current-state interpretation and acceptance criteria across
passes, reuse of interpreted assertions, then wider clinical/payer/outcome bindings
and warehouse-backed discovery/action operators. All broad product goals remain.
