# Scoped documentary commands and work preservation

G5 remains partial. This delivery adds an explicit local command path and repairs
a task-context collision found during its actual workflow verification. It does
not qualify a language model, establish clinical accuracy, or promote a route.
The computed finite local release remains **4/9 engineering requirements**.

On `/stack`, **Run scoped source-review command (candidate)** compiles respiratory
or behavioral documentary review commands with exact patient lists, whole-roster
scope and exclusions. It validates case-sensitive IDs against the received roster,
preserves the original question, and abstains on unsupported syntax, dates,
recommendations, contradictory scope and unknown IDs. Unsupported UI filters are
rejected before dispatch. Ordinary planning remains the default.

The result continues through the existing population decision, buyer capabilities,
received payer context, internal task and saved follow-up. The command graph,
compiler identity and snapshot are retained in existing decision storage. Saving
recompiles the command and rejects changed compiler or cutoff identities. No new
model, warehouse, task database or externally executing agent was installed.

The verified question selects P-1004 and P-1002 and explicitly excludes P-1003.
It retains two selected members: one documentary nomination and one with unresolved
need. Another command excludes two members from the full 1,614-person roster and
reconciles 1,612 selected members. No clinical eligibility or benefits are inferred.

creates a new service plan for the same source/need/service task, and queueing it
refreshes the old task context and removes its prepared handoff. The first HTTP
success receipt is therefore insufficient preservation evidence; the later
`final/verification.json` supersedes that conclusion.

The shared population queue now rejects a different saved plan for an existing
task before calling the legacy refresh path. Population queue and batch operations
use the same reentrant lock. A regression proves the original handoff and owner
remain unchanged after rejection. Legacy direct capability endpoints retain their
prior behavior; global cross-process transaction hardening remains G6 work.

The affected synthetic task was restored through ordinary audited queue/handoff
events, at revision 5; no history was erased. Its old financial follow-up correctly
became historical and was recomputed and reopened as current. The initial candidate
link remains historical. Final verification uses a separate declared synthetic
buyer and one new internal task, avoiding further changes to prior work.
