## Important distinctions

- `clinical_core/agere/runtime.py` already exercises some earlier components
  together. Calling those components wholly unbuilt would be inaccurate.
- `clinical_core/agere/training.py` trains a BioClinical action head and a narrow
  synthetic routing threshold. The latest question interface does not use that
  as a general calibrated model-selection policy.
- Causal, facility, network, coding, allocation and contract functions accept
  explicit input tables through existing APIs/CLI paths. Their existence does
  not mean natural-language questions can select a complete warehouse cohort,
  build the required inputs and obtain a supported answer.
- The research catalog maps established mathematics to proposed jobs. Catalog
  registration does not invoke those functions. No new mathematical theory or
  superiority over competing products has been established.
- Additional researched models are candidates, not an installed universal
  ensemble. Qwen3-4B is an inactive earlier experiment; Jev/Perplexity/Claude have
  actual adapters. Perplexity's Qwen-derived decision checkpoint is a separate
  model/task, not evidence that the local Qwen3-4B reader should be promoted.
- Execution agents remain intentionally deferred at the user's request.
- Missing warehouse fields and missing implementation are separate. Required
  inputs must remain explicit when the other chat's synthetic sources lack them.

## Build sequence

Apply the completed research intake's core ordering to the engineering sequence
below: accountable cohort and therapy interpretation → persistent program work →
outcome/commercial/OAP measurement → typed downstream results/replay → advanced
methods with a demonstrated core use. Longitudinal sequence/context execution is
now built; its remaining clinical meaning and historical replay work stays open.

1. Extend the existing cohort/event core into shared data, concept, relationship,
   outcome and required-input contracts. Build composable analytical dependencies
   across clinical, utilization, access, provider, program and financial questions.
2. Build general longitudinal and observation state: distinct events within a
   record, narrative dates, episodes, corrections, copied evidence, barriers and
   uncertainty. Expand condition/therapy interpretation as reusable domain logic.
3. Connect discovery, pathway investigation, case-mix-aware comparisons and
   forecasting through the registry with actual warehouse adapters. Use supported
   causal designs for causal questions; separate prediction from intervention benefit.
4. Connect intervention evidence, patient goals, capacity and versioned payer rules
   to supported recommendations. Add update intake and impact analysis, then
   measure/site/contract operations using explicit definitions and attribution.
5. Connect reviewed skill training and cost-aware routing to these capabilities.
   Measure local compute, provider usage, failures, caches and review burden;
   dependency reuse and economics apply throughout the sequence.

Focused source, arithmetic and contract checks belong alongside each addition.
Another round of unchanged reader comparisons is not the next implementation
milestone. Completion means the relevant question can execute its required
operators against the warehouse, with evidence and explicit unresolved inputs.
