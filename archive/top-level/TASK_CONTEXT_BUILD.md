# Agere shared task context — October 9, 2026

Implemented in the [workbench](http://127.0.0.1:8885/stack). All patient data and
results here are synthetic. This is context assembly, not clinical validation.

## Executable behavior

`clinical_core/agere/clinical/context_builder.py` reuses the warehouse, longitudinal
annotation/event ledger, clinical prerequisite artifact and exact installed program
versions to assemble task-specific evidence over a complete selected population.
The graph has a `context` operation. The economical compiler and workbench expose
**Build medication context**, **Build outside-care context** and **Build affordability
context**. The underlying component supports explicit source/concept scopes.

- Includes mapped unannotated received narrative paragraphs and literal structured
  records. Never substitutes simulator original text for received OCR.
- Preserves source hashes, exact field/offsets, source identity and separate clocks.
  Historical references are not refreshed by a newer document date.
- Prioritizes requested concepts, qualified/history annotations, exception and
  source-coverage relations, opposing reports and conservative caution language.
  Protection is heuristic, not validated clinical recall. Opposing reports across
  time may represent change, rather than simultaneous contradictions.
- Stores provenance once per source and references it from evidence units. No
  generated summary or new clinical fact is created.
- Accounts for every omitted unit under an explicit UTF-8 byte budget. Partial
  packets remain inspectable but cannot pass its complete-case handoff guard.
  Absence of a record or annotation is not treated as absence of care.
- Persists compressed derived receipts in population stack v3's `contexts.sqlite3`.
  Cache keys include task/scope/budget, source snapshot, reader/state dependencies,
  selected policy versions and implementation identity.
- `/api/stack/context?id=...` verifies dependencies before returning a receipt.
  `for_model` additionally rechecks source hashes and applies the caller's actual
  tokenizer, capacity and explicit prompt/output reservation without truncation.

## Executed results

Source: `artifacts/agere-task-context-v1/run.json`, generated by `run_task_context.py`.
Each workflow evaluated all **10,000** patients with a **24,000-byte** context budget.

| Context | All mapped units in declared source scope fit | Other budget omissions | Protected evidence exceeds budget |
|---|---:|---:|---:|
| Medication | 5,769 | 2,311 | 1,920 |
| Outside care | 6,219 | 3,033 | 748 |
| Affordability/access | 6,332 | 2,740 | 928 |

Each row partitions the same population; do not add rows as unique patients.
These are transport/budget counts, not correctness scores or eligibility. A
complete requested scope is not a complete chart or adequate clinical context.
Missing evidence and unsupported interpretation can remain in a complete packet.

First complete builds took 21.82, 19.41 and 22.62 seconds respectively on this laptop.
There were **zero paid API calls**. Local hardware cost was not measured. Byte
savings must not be presented as token or dollar savings without measurement.

## Verification

**30 focused tests passed** (`test_task_context` and `test_analysis_graph`), covering
source/quote binding, patient boundaries, late arrivals, received OCR, qualified
and historical evidence, omissions/overflow, multilingual byte accounting, native
token limits and graph compilation. Existing frozen Kev/d1 experiments are intact.

`artifacts/agere-task-context-v1/integration.json` records live HTTP execution of
all three full populations, cached replay and the medication question's local
compiler route. A real installed `models/kev-qwen35-base` tokenizer counted
**6,051 tokens** for one complete packet. It fit **8,192** with **1,024** reserved;
a smaller capacity was correctly rejected. No model inference was performed.
The maximum ASCII-length planner question produced a **19,239-byte** request,
inside its unchanged **20,000-byte** bound. Browser inspection confirmed counts
and retrieval of an exact patient context receipt.

## Still unfinished

The existing ranked-evidence Jev/Perplexity review route remains unchanged. The
new graph operation and guarded consumer interface do not replace every model
input path yet. Kev/d1 remain experimental; neither has been promoted.

Large charts need explicit task decomposition and bounded evidence passes with
source-bound reconciliation. Raising budgets alone does not resolve ambiguity or
improve economics. Unmapped fields and limited annotation vocabulary remain
limitations. Broader relation/current-state interpretation, reviewed clinical and
payer rules, outcome/attribution definitions, warehouse discovery and supported
action recommendations remain build work. `NEXT_STACK_BUILD.md` is partially
implemented, not complete.
