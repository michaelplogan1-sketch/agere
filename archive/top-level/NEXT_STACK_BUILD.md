   use, holds and completed care remain distinct. Process complete in-scope
   populations; top-k retrieval does not define the population denominator.
2. **Evidence and observation reconciliation.** Bind structured and narrative
   assertions to the longitudinal ledger and terminology identity. Preserve
   corrections, stale/copy-forward evidence and competing accounts. Distinguish
   unavailable source, delayed record, unobserved event, unsupported interpretation
   and documented noncompletion. Return the particular additional evidence needed
   when a distinction cannot be resolved. Do not invent probabilities of outside
   care or declare an unavailable source complete.
3. **Economical skill routing and learning.** Reuse exact version-bound results;
   use code for established transformations. Send only unresolved bounded packets
   to suitable specialists and reserve frontier calls for justified complex work.
   Keep Kev/d1 in the proposal/training comparison branch until a skill earns
   promotion. Build new training examples with observable evidence labels,
   difficult negatives and exact support spans; retain machine supervision as such.
   Separate source families and fresh evaluation worlds. Do not train on the
   existing reserved answers. Track local compute, failed calls and review load.
4. **Connect interpretation to questions and work.** Expose the shared reconciled
   state through the existing analysis graph and workbench. Return supported
   findings, unresolved alternatives, next evidence/review steps, source and rule
   versions, full denominator accounting and cost receipts. Refresh only affected
   findings after evidence, rule or model changes. Existing program queues consume
   explicit proposals; an interpretation alone does not mark an action completed.

## Concrete completion criteria

The same warehouse question path must answer a cross-source medication review,
an outside-care/completion question and an access-barrier question using shared
primitives. Each answer must account for the complete defined population and show:

- What the evidence establishes and its effective/documentation dates.
- Which accounts conflict or require interpretation or additional sources.
- What supported review or information-acquisition step follows.
- Which versioned clinical/program/measure prerequisites remain unmet.
- Which code/model routes ran, what was reused, and their measured costs.

HFrEF-to-PharmD is an end-to-end acceptance example, alongside other population
questions. The milestone is complete when the question executes on the synthetic
warehouse and produces inspectable, persistent results. A larger question catalog,
diagram or unchanged model benchmark is not completion. Focused correctness
checks accompany each implemented capability.

## Following milestones

After the shared interpretation boundary, extend versioned protocol and payer-rule
application, outcome/attribution/denominator contracts and program-to-payment
accountability. Connect population discovery and forecasts through those same
inputs. Use case-mix shrinkage for sparse provider comparisons, change detection
with observation-process checks for trajectories, false-discovery controls for
large pattern searches, and value-of-information reasoning for missing evidence
when defensible inputs exist. Causal effects require a supported identification
design; prediction is a different target.

Each mathematical component needs an actual input adapter, explicit assumptions
and a useful warehouse output. These are established methods with proposed
integration advantages; no new theorem, unique architecture or superiority to
commercial products is claimed by this plan.
