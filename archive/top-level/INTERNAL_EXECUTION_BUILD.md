# Scoped internal worker and packet review — October 10, 2026

The buyer-service task now has a local execution adapter with credential-scoped acknowledgement, completion receipts and internal packet review. The adapter checks four evidence dependency layers against the exact task revision, plan, readiness receipt and adapter identity. It performs no clinical or external action. Existing source, coverage, participation and documentary engines are reused unchanged.

Credentials are provisioned by the local administration CLI, scoped to one existing buyer/service and packet-worker or packet-reviewer role, and expire or can be revoked. Only a random token's hash is stored. No HTTP provision/revoke endpoint exists. The browser clears the password input after use and does not persist credentials. Credential possession is authenticated; human identity, professional qualification and clinical authority are not verified. Other legacy loopback endpoints retain their existing self-reported actor model. This is not production identity management or universal application authorization.

Duplicate requests replay immutable receipts; a different request for the same packet reuses the completion. Revoked/expired credentials cannot replay. Review revisions prevent lost updates. Changed sources, service configuration, participation, task state or packet attachments invalidate currentness, but preserve historical evidence. Internal review records either acceptance for further evidence review or a need for more evidence, with a required operational follow-up date. It does not clear any clinical prerequisite or assert service completion. The operational UTC calendar is separate from the 2029 synthetic clinical snapshot.
