## 1. What does DAIR teach about context engineering for agents, and which of it applies to the small-model restatement prompt, the SQL-writing prompt and the last-resort agent?

### Takeaway
DAIR's own context-engineering guides are practical and uncited (no papers, no benchmark numbers): layered context (system / task / tool / memory), explicit allowed values and formats, tool "when to use" guidance in the system prompt, minimal sub-agent inputs, summarise tool output before it enters context, and an observe-and-patch iteration loop. The measured evidence sits in the 2026 weekly paper list, where compaction, explicit state, description rewriting for routed menus and cache-aware trimming all have numbers.

### Cited Findings

**DAIR's own guides (DAIR claims, no cited papers)**
- Definition: context engineering is "designing, testing, and iterating on the contextual information provided to AI agents"; it covers system prompts, task constraints, tool descriptions, memory and error handling. — [Context Engineering for AI Agents](https://www.promptingguide.ai/agents/context-engineering)
- Four-layer context: System (identity, capabilities), Task (instructions for this task), Tool (description and usage guidance per tool), Memory (relevant history and learnings). *Test here:* restructure the last-resort agent prompt into these four labelled blocks and compare answered-and-number-checked rate on the existing hard-question set. — [same page](https://www.promptingguide.ai/agents/context-engineering)
- Replace vague instructions with numbered steps and state required versus optional actions, quality standards, output format and decision criteria. *Test here:* numbered procedure in the SQL-writing prompt (identify population, date scope, definition, then write) versus current prose, scored by second-model row reproduction rate. — [same page](https://www.promptingguide.ai/agents/context-engineering)
- Named pitfalls: over-constraint ("NEVER skip", "ALWAYS exactly 3"), under-specification, and ignoring error cases. DAIR's remedy for over-constraint is to let the agent deviate if it documents its reason. — [same page](https://www.promptingguide.ai/agents/context-engineering)
- Error-handling block in the prompt: retry a failed call once with a rephrased query; if it fails again record the failure and continue; escalate past a failure threshold; never stop silently. *Test here:* add an explicit "SQL error or empty result" rule to the agent and count turns wasted on repeated identical failing queries inside the 8-turn budget. — [same page](https://www.promptingguide.ai/agents/context-engineering); [Deep Dive](https://www.promptingguide.ai/agents/context-engineering-deep-dive)
- Context validation checklist: completeness, clarity, consistency, testability. Success measures DAIR lists: task completion rate, behavioural consistency across similar inputs, error rate, user satisfaction, debugging time. — [same page](https://www.promptingguide.ai/agents/context-engineering)
- Observability: log every agent decision, tool call and outcome, and review every run; treat odd behaviour as a prompt for a context fix. — [same page](https://www.promptingguide.ai/agents/context-engineering)
- Tool descriptions: DAIR says the biggest gains often come from explaining in the system prompt what each tool does and **when** to use it, more than from parameter specs. *Test here:* add when-to-use text for the SQL tool versus the document-open tool and measure wrong-tool first calls. — [Deep Dive](https://www.promptingguide.ai/agents/context-engineering-deep-dive)
- Define allowed values explicitly; without it DAIR's agent drifted between "pending / to-do" and "completed / done / finished". *Test here:* enumerate the exact JSON protocol field values and count protocol-parse failures per 100 agent runs. — [Deep Dive](https://www.promptingguide.ai/agents/context-engineering-deep-dive)
- Flexible versus rigid tool instructions: flexible wording let the agent skip or merge searches; DAIR recommends rigid wording for production. — [Deep Dive](https://www.promptingguide.ai/agents/context-engineering-deep-dive)
- Sub-agent isolation: one agent doing task management, memory, search and reporting produced long context, forgotten steps and inconsistent behaviour; a dedicated worker fixed it. Give the worker only the query text; have it return findings, error states and execution metadata. Use a stronger model to plan and a cheaper one to execute. *Test here:* document reading as an isolated cheap worker that returns quote plus location only, compared with the agent opening documents in its own context. — [Deep Dive](https://www.promptingguide.ai/agents/context-engineering-deep-dive)
- Context-length controls DAIR lists: isolate with separate agents, use memory tools, summarise long outputs before adding them to context, clear task lists between queries. — [Deep Dive](https://www.promptingguide.ai/agents/context-engineering-deep-dive)
- Inject the current date; DAIR also suggests exposing date as a tool called only when needed, and giving the exact ISO 8601 format with a rule for deriving start and end dates from a time phrase. *Test here:* relative-date questions ("last quarter", "past 12 months") through the small-model parameter filler with and without an injected date and format rule. — [Context Engineering Guide](https://www.promptingguide.ai/guides/context-engineering-guide)
- Structured output: list every field with type and allowed values, mark optional fields and say they may be null, state scales and counts explicitly, give a JSON example, use an output parser. The guide's own sample output contains `"priority": 1.2` against a stated integer scale. — [Context Engineering Guide](https://www.promptingguide.ai/guides/context-engineering-guide)
- Delimit user input with tags such as `<user_query>`. — [Context Engineering Guide](https://www.promptingguide.ai/guides/context-engineering-guide)
- Cache prior plans in a vector store and look them up by similarity before calling the model, because every call adds latency and cost. — [Context Engineering Guide](https://www.promptingguide.ai/guides/context-engineering-guide)
- DAIR's stated position on measurement: "If you are not measuring all these things, how do you know whether your context engineering efforts are working?" Compression, context management and context safety are marked work-in-progress on that page. — [Context Engineering Guide](https://www.promptingguide.ai/guides/context-engineering-guide)
- Deep agents: keep an updatable plan, store intermediate work outside the conversation (files, notes, database), combine agentic search with semantic search, give each sub-agent a clean context, include a dedicated verifier. DAIR cites ReasoningBank (arXiv:2509.25140) and Agentic Context Engineering (arXiv:2510.04618) for memory, and Anthropic's "Writing tools for agents". DAIR notes the Cognition "Don't build multi-agents" counter-argument and says he is sceptical of it. — [Deep Agents](https://www.promptingguide.ai/agents/deep-agents)
- Agent components page: short-term memory is the context window; long-term is an external store; planning is imperfect and needs progress checks. No sources cited. — [Agent Components](https://www.promptingguide.ai/agents/components)

**Papers DAIR highlighted in 2026 with measured results on context handling** (all from the [2026 list](https://github.com/dair-ai/ML-Papers-of-the-Week/blob/main/years/2026.md))
- **Context Compaction** (2611.05306, week of Nov 2). NVIDIA. Paper reports: one action per context with a short carried state gives Claude Opus 4.5 70.2 on SWE-bench Verified versus 70.0 with full history; median peak context falls from 32K to 8K tokens. *Test here:* agent carries a short state summary plus the last tool result instead of all 8 turns; compare accuracy and tokens.
- **SKILL.state** (2608.26263, Aug 31). Google and others. Replace append-only history with immutable spec + mutable structured state + latest observation; reasoning discarded once it yields a validated JSON-patch state update. Paper reports accuracy up and cumulative tokens down; prompt size O(1) in steps. *Test here:* agent state object (tables checked, numbers seen with provenance, open sub-questions) patched each turn.
- **What Compaction Destroys** (2608.22752, Aug 24). Paper reports Claude Code compaction on Sonnet 4.6 keeps 53% of safety rules after one round and 10% after five; type-aware retention keeps 2 to 4 times more with 96% recall. DAIR's reading: anything that depends on exact wording needs a different retention policy. *Test here:* if follow-up history is ever summarised, keep measure definitions and scope constraints verbatim and check they survive.
- **Lost in Compaction** (2608.11242, Aug 10). Session constraints ("do not X until I confirm") are silently dropped by compaction. *Test here:* a follow-up set where turn 1 sets a population or date scope and turn 4 depends on it, through the four-question memory.
- **Context Management as Code** / Scroll (2608.21690, Aug 24). Alibaba. State lives in a persistent kernel; only printed projections enter the prompt; evicted spans stay retrievable. Paper reports 94.8% LongMemEval_S, 73.1% BEAM_10M with Qwen3.8-Max. *Test here:* agent sees only a row count and head of SQL results, with a tool to page further.
- **Cache Engineering for Agents** (2610.28577, Oct 19). Paper reports a rolling drop of old tool responses scores 1.7 points higher and costs 27.7% less than threshold-triggered summarisation. *Test here:* drop tool results older than two turns in the agent and compare.
- **Skill++** (2611.00544, Nov 2). Rewrite each new skill's description to say what it supports, how it differs from its nearest neighbour and what it excludes. Paper reports routers pick all required skills for 76.3% of queries versus 36.4% with original metadata at 731 skills; +23.1 points average across three benchmarks and five routers. *Test here:* rewrite the ~60 method descriptions contrastively against each method's nearest neighbour and measure small-model method-selection accuracy.
- **Demystifying Agent Skills** (2608.14036, Aug 17). Paper reports skills help by procedural anchoring in 65.7% of helpful cases versus 4.5% for knowledge injection; actual-use precision falls from 29.6% to 3.3% as the pool grows from 5 to 100. *Test here:* shortlist methods (retrieval or the typed classifier) to about 5 to 10 before the small model sees the menu, compared with the full 60.
- **The Skill Trigger Bottleneck** (2608.12610, Aug 17). DAIR's summary states fewer than 100 reliable trigger slots in a system prompt and recommends deciding per skill whether it must fire unasked. *Test here:* same shortlist experiment.
- **Compositional Skill Routing** (2606.18051, Jun 14). Feeding retrieval results back into decomposition lifts accuracy from 51.0% to 67.7%. *Test here:* multi-method questions decomposed with the candidate method list visible.
- **Progressive Disclosure, Measured** (2607.17598, Jul 20). Benefit of description-then-detail loading is large with a weak harness and near zero with a strong one. *Test here:* two-stage method menu (names first, examples on selection) against the flat menu.
- **Structured Output Collapses Diversity** (2607.18476, Jul 20). 44 models; requesting JSON shifts 53% of stable chat defaults; decoder enforcement adds no further compression. *Test here:* evaluate the restatement and parameter-fill prompts in the JSON form they ship in, not a chat form.
- **Evaluating AGENTS.md** (2602.11988, Feb 23), **Codified Context** (2602.20478, Feb 23), **Lossless Context Management** (Feb 16, papers.voltropy.com/LCM), **Active Context Compression** (2601.07190, Jan 12), **Memory Control for Long-Horizon Agents** (2601.11653, Jan 19), **Context Language Models** (2609.37725, Sep 28), **AutoCompact** (2610.02163, Sep 28) and **Context Engineering 2.0** (2510.26493, Nov 2025) appear in the lists; I captured titles and IDs only, not their summaries.

### Inferences
- Small-model restatement prompt: the directly applicable items are explicit allowed values, contrastive method descriptions (Skill++), a shortlisted menu (Demystifying Agent Skills), delimited user text and date injection. The 60-item flat menu is inside the regime where the skills papers report selection precision falling.
- SQL-writing prompt: numbered procedure, explicit output contract, definitions kept verbatim, and a retrieval lookup of similar saved recipes as in-context examples (DAIR's "cache prior plans" pattern, which the saved-recipe store already supports).
- Last-resort agent: an 8-turn, 150-second agent is short enough that compaction matters less than state discipline. The applicable items are a structured state object, truncating SQL results before they enter context, when-to-use tool text and an explicit error rule.
- DAIR's own guides on this topic are built around an n8n deep-research agent and are illustrative. Treat them as checklists, and treat the weekly papers as the evidence.

### Gaps
- The Academy workshop "Context Engineering for AI Agents", the course module "Context Engineering for AI Agents" (lessons "AI Agent Architecture & System Prompts", "Tuning an Agent's Tool Descriptions") and the workshop "Scaling Memory for AI Agents" are Pro (login and paid). Titles only were readable; content was not read.
- The nlp.elvissaravia.com newsletter was not opened; a search for it returned no pages from that domain. The dair.ai blog copy of the Context Engineering Guide (dated 24 December 2025 in the search result) was not opened separately; the promptingguide.ai copy was.
- DAIR's guides do not cover compaction or structured-output validation in any depth, and cite no papers for context engineering.
- Summaries for the eight title-only papers at the end of the findings list were not extracted.

## 2. What agent design patterns and evaluation practices does DAIR recommend?

### Takeaway
DAIR teaches the standard workflow patterns (prompt chaining, routing, parallelisation, orchestrator-workers, evaluator-optimizer) and says to prefer workflows when predictability and cost matter, which describes this ladder. Its public pages are thin on evaluation; the detail is in paid course modules. The 2026 papers DAIR picked give concrete, measured guidance: use a separate reviewer over self-checks, calibrate any LLM judge against a verifiable signal, use chance-corrected agreement, and re-run to measure noise.

### Cited Findings

**DAIR's own pages**
- Workflows are "systems where LLMs and tools are orchestrated through predefined code paths". Use workflows when requirements are stable, predictability is essential, debugging matters or cost is critical; use agents for open-ended tasks. Hybrid designs (a workflow that routes to agents for open-ended subtasks) are described as common in production. — [AI Workflows vs AI Agents](https://www.promptingguide.ai/agents/ai-workflows-vs-ai-agents)
- Routing: a classifier sends each request to a specialised chain or model; cited benefit is cost saving from selective model use. Prompt chaining: place quality gates between steps. Parallelisation: for independent subtasks, including independent verification. — [same page](https://www.promptingguide.ai/agents/ai-workflows-vs-ai-agents)
- Workflow practice list: document each step, add fallback paths, put validation gates between critical steps, track latency and success rate per step. *Test here:* per-rung dashboard of hit rate, correct rate, latency and cost on the existing question sets. — [same page](https://www.promptingguide.ai/agents/ai-workflows-vs-ai-agents)
- The page links Anthropic's "Building Effective Agents"; it does not itself describe orchestrator-workers or evaluator-optimizer. Those appear as paid modules in the Advanced AI Agents course. — [same page](https://www.promptingguide.ai/agents/ai-workflows-vs-ai-agents); [Advanced AI Agents](https://academy.dair.ai/courses/advanced-ai-agents)
- Verification is presented as a core component of deep agents, automated (LLM-as-a-judge) or human; risks named are hallucination, sycophancy and prompt injection. — [Deep Agents](https://www.promptingguide.ai/agents/deep-agents)
- LLM-as-a-Judge lab outline (Pro): name the qualities to score; yes/no verdict first; then a three-part rubric returning parseable JSON; "Measure whether the judge can be trusted by comparing its scores against human labels and reporting the agreement rate"; harden with reason-first scoring and temperature 0; document a failure mode; ship an evaluation report. Only these lab descriptions were readable. *Test here:* any judge used on narrative answers is first scored against a hand-labelled set and the agreement rate reported. — [LLM-as-a-Judge lab](https://academy.dair.ai/courses/llm-as-a-judge)

**Papers DAIR highlighted (2026 list unless stated)**
- **Verification in Agent Harnesses** (2610.34577, Oct 26). Alibaba and Cornell, 17 designs, seven models. Paper reports: system-role verification instructions +3.3 / +3.9 points (Terminal-Bench / SWE-bench Verified); a separate critic +5.9 to +9.5 on Terminal-Bench at 1.13x to 1.25x cost and +3.9 to +6.6 on SWE-bench at 1.00x to 1.04x; authors recommend avoiding completion-time self-checking; reviewing the changes beats reviewing the trajectory. *Test here:* the independent second-model row reproduction is this pattern; extend it to agent answers (a separate reviewer sees question, SQL and rows, not the trajectory) and measure caught errors per added cost.
- **VeriHarness** (2610.00972, Oct 5). Google. Agreement across rollouts can hide shared errors; a "consensus challenger" tests claims all rollouts share. Paper reports +6.2 points (Gemini 3.5 Flash) and +6.4 (Claude Opus 4.8) over a single rollout. *Test here:* when writer and reproducer agree, sample cases and check for a shared wrong definition (same denominator error in both).
- **The Consistency Illusion** (2606.04223, Jun 7). Output agreement can hide disagreement in reasoning. *Test here:* compare the two models' SQL structure (joins, filters, denominators), not only their rows.
- **GAUGE** (2609.12191, Sep 14). Amazon, 25 agents. Paper reports 57.5% of conversations judged "satisfied" had failed the task; among near-equal agents the judge picks the lower-reward one on 31% of pairs; judges favour their own model family. Fix: a judge-free completion bit, and trust the judge only after calibration against a verifiable reward. *Test here:* prefer deterministic row and number checks for release decisions; use a judge only where it has been calibrated against them.
- **Reliability without Validity** (2606.19544, Jun 21). Audit of 21 judges, nine providers: exact-match agreement does not correct for chance and overstates judge quality. *Test here:* report Cohen's kappa (or similar) for classifier and judge agreement, not raw agreement.
- **Judges as a Lifecycle** (2608.18300, Aug 24). Netflix. Four phases: define criteria with human-labelled benchmarks and rationales, tune the rubric, deploy, monitor drift with a review gate. *Test here:* re-score the judge against fresh labels on a schedule.
- **JEV-as-a-Judge** (2609.26550, Sep 21). A decision-only judge returning label probabilities: paper reports $0.044 per 1,000 judgments versus $12.182 for GPT-6; within 3 points on ordinary judgments (92.2% versus 93.5% RewardBench) but 9 to 20 points worse on derivation checks (78.6% versus 93.1% JudgeBench); errors cluster in low-confidence decisions, so accept-when-confident, escalate-otherwise kept 99% of GPT-6 accuracy at about 57% of the fee on 510 pairs; the threshold did not transfer across fallback models. *Test here:* this is the ladder's typed-judgment rung; plot accuracy against probability on a labelled set and set the escalation threshold per downstream model.
- **Verification as a Scaling Axis** (2607.05391, Jul 5). Read a continuous score from scoring-token logits; improve with finer score granularity, repeated evaluation and criteria decomposition. Paper reports 73.3% on MedAgentBench among others. *Test here:* decompose "is this answer supported" into per-number and per-claim checks.
- **LLM-as-a-Verifier** (Apr 13, llm-as-a-verifier.github.io, no arXiv ID in DAIR's link) and **The Universal Verifier for Agent Benchmarks** (2604.06240, Apr 6): non-overlapping rubric criteria, separate process and outcome scores; paper reports false positives near zero versus 45%+ for a prior verifier.
- **Skill-Based Agentic Evaluation** (2609.16487, Sep 14). Adobe. Store each reference answer as a function run against the live system at evaluation time; a judge splits response and computed answer into atomic facts. *Test here:* express gold answers for the question sets as saved SQL so they stay valid when the warehouse refreshes.
- **DataSpace** (2608.03451, Aug 3). 410 analytics tasks over databases, files and long documents; deterministic scoring by header-invariant column alignment, type- and precision-aware normalisation and order-aware row comparison; swapping the harness with a fixed model moves accuracy 15.36 points; best 66.34%. Used for the KDD Cup 2026 Data Agents competition. *Test here:* adopt the same row-comparison rules for the second-model reproduction check and for the question-set scorer.
- **AlphaEval** (2604.12162, Apr 13). 94 production tasks from seven companies; six failure modes named: cascade dependencies, subjective judgment collapse, retrieval failures, cross-section inconsistency, constraint misinterpretation, format compliance. *Test here:* use these as error-analysis labels on failed questions.
- **The Fragility of Self-Improving Agents** (2608.18066, Aug 17). Reported gains from memory-based self-improvement shrink when runs are repeated and task order is shuffled. *Test here:* repeat each evaluation at least three times and shuffle order before claiming that saved recipes improve later answers.
- **When Is Routing Meaningful** (2607.09197, Jul 12). A router is meaningful only if the routed targets behave differently and assignments are stable under paraphrase; learned KNN routers collapsed under paraphrase while a prompted router held. *Test here:* paraphrase each test question three ways and check that it lands on the same rung and method.
- **Agent-as-a-Router** (2606.22902, Jun 21). Paper reports that giving a router per-task-type performance statistics yields a 15.3% relative gain. *Test here:* give the escalation step each rung's measured accuracy by question type.
- **Weak-Model Critic-Comparator** (2605.14163, May 18). Sample k=8 candidates from a weak model and select using execution signals; paper reports GPT-5.4 nano reaching 76.4% on SWE-bench Verified. *Test here:* small model writes several SQL candidates, executed and selected by result agreement, compared with one frontier call.
- **Meta-Harness** (2603.28052, Mar 30). Changing the harness around a fixed model can give a 6x gap; paper reports +7.7 points on online text classification with 4x fewer context tokens.
- Also listed, titles and IDs only: Agent-as-a-Judge (2601.05111), Holistic Agent Leaderboard (2510.11977), TIR-Judge (2510.23038), Towards a Science of Scaling Agent Systems (2512.08296), Workflow Optimization for LLM Agents (2603.22386), Model Pool Selection (2609.17306), Intelligent AI Delegation (2602.11865), Efficient Agents (2601.14192).

### Inferences
- The ladder is a routing-plus-cascade workflow with an agent at the end, which is the hybrid DAIR describes; nothing in DAIR's material argues for making it more agentic.
- The system's two existing verification steps (code checks every number; a second model reproduces the rows) are of the kind the 2026 evidence favours over self-checking. The uncovered risk the papers point to is shared error when both models agree.
- The cheap typed-judgment rung has direct external support in JEV-as-a-Judge, including the caveat that it is weak on derivation checks and that its threshold must be set per fallback model.
- The largest evaluation gaps relative to DAIR's selections are: no chance-corrected agreement, no repeat runs for variance, no paraphrase stability test for routing, and gold answers that can go stale.

### Gaps
- DAIR's teaching on eval dataset construction, metric selection, guardrails, trace annotation and error analysis is in Pro lessons and was not read. Publicly, DAIR gives only lesson titles.
- The two free items most relevant here (Elements of AI Agents; the Jev-as-a-Judge lab) were not opened; only catalogue descriptions were read.
- A `dair-academy` connector exists in this environment but requires the user to authorise it (via `/mcp`); it was not usable, so no logged-in content was read.
- Orchestrator-workers and evaluator-optimizer are not described on the public promptingguide.ai pages I opened.

## 3. What prompting techniques in the Prompt Engineering Guide have evidence for text-to-SQL, few-example classification, extraction with citations, self-consistency or verification?

### Takeaway
The Guide's technique pages are short explainers that each cite the originating paper; most give a worked example and no benchmark numbers. It has no dedicated text-to-SQL evidence (one schema-in-prompt example), no chain-of-verification page, and no DSPy or GEPA page. The strongest quantified item for this system is the job-classification case study (clear instructions and repetition mattered most; few-shot chain-of-thought underperformed zero-shot on a task needing no expert knowledge).

### Cited Findings
- **Text-to-SQL.** The Guide's only item is a prompt-hub example: table schema in a delimited block followed by the plain-language request, run on GPT-4. No evaluation, benchmark or reference. — [Generate MySQL Query](https://www.promptingguide.ai/prompts/coding/mysql-query)
- **Few-shot demonstrations.** Citing Min et al. 2022 (arXiv:2202.12837): the label space and the distribution of input text in the demonstrations both matter; format matters; even random labels beat no labels; labels drawn from the true label distribution help. Few-shot is unreliable for multi-step reasoning. Other citations: Brown et al. 2020 (arXiv:2005.14165), chain-of-thought (arXiv:2201.11903). *Test here:* make the example phrasings in the method menu cover every method (full label space) and mirror real user wording; compare against the current examples. — [Few-shot Prompting](https://www.promptingguide.ai/techniques/fewshot)
- **Classification case study.** Clavié et al. 2023 (arXiv:2303.07142), GPT-3.5 on entry-level-job classification. Paper reports (per DAIR's page): baseline 65.6 F1, fully engineered prompt 91.7 F1 (precision 86.9, recall 97); few-shot CoT 78.4 versus zero-shot CoT 81.4; role in system message plus task in user message 87.5; forcing a strict output template lowered performance in every case on GPT-3.5 (not seen in early GPT-4 testing); repeating key instructions was among the biggest drivers; tiny wording changes moved F1. *Test here:* for the small-model method chooser, compare (a) instructions repeated at the end, (b) reason-then-answer versus answer-only JSON, on the labelled question set. — [Graduate Job Classification Case Study](https://www.promptingguide.ai/applications/workplace_casestudy)
- **Self-consistency.** Wang et al. 2022 (arXiv:2203.11171): sample several reasoning paths and take the majority answer; DAIR says it helps arithmetic and commonsense reasoning. The page gives one worked example and no numbers. *Test here:* three samples of the small-model restatement; act only when at least two agree, otherwise escalate; measure wrong-method rate against escalation rate. (See VeriHarness in section 2 for the limit of agreement as a signal.) — [Self-Consistency](https://www.promptingguide.ai/techniques/consistency)
- **Program-aided language models.** Gao et al. 2022 (arXiv:2211.10435): the model writes code as its reasoning and a runtime computes the answer. One date-arithmetic example, no numbers on the page. *Test here:* this is the system's existing design (SQL computes, the model does not); extend to date-window arithmetic by having code, not the model, resolve relative dates. — [PAL](https://www.promptingguide.ai/techniques/pal)
- **ReAct.** Yao et al. 2022 (arXiv:2210.03629). Per DAIR's page: ReAct beats act-only on HotpotQA, FEVER, ALFWorld and WebShop; beats CoT on FEVER and trails it on HotpotQA; the best setup combines ReAct with CoT plus self-consistency; ReAct depends heavily on retrieval quality and non-informative results derail it. *Test here:* log how often the agent's first SQL result is empty or uninformative and whether the run recovers within 8 turns. — [ReAct](https://www.promptingguide.ai/techniques/react)
- **Generated knowledge.** Liu et al. 2022 (arXiv:2110.08387): generate relevant facts first, then answer. One example, in which different generated statements flipped the answer; no accuracy numbers on the page. *Test here:* have the SQL writer first restate the applicable measure definition from the supplied definitions before writing SQL; score reproduction rate. — [Generated Knowledge](https://www.promptingguide.ai/techniques/knowledge)
- **Automatic prompt optimisation.** APE, Zhou et al. 2022 (arXiv:2211.01910): a model proposes candidate instructions, each is scored on a target model, the best is kept; it found a zero-shot CoT phrase that beat "Let's think step by step" on MultiArith and GSM8K. The page also lists OPRO (arXiv:2309.03409), Prompt-OIRL (arXiv:2309.06553), AutoPrompt (arXiv:2010.15980), prefix tuning (arXiv:2101.00190) and prompt tuning (arXiv:2104.08691). — [Automatic Prompt Engineer](https://www.promptingguide.ai/techniques/ape)
- **Newer optimisers, from DAIR's weekly list, not the Guide.** CASD (2609.26261, Sep 28, Microsoft): give a coding agent the whole trajectory corpus, have it compute corpus-wide failure statistics and write behavioural rules in one pass; paper reports +16.6 points average over baseline versus +10.9 for GEPA and +5.3 for SkillOpt across four benchmarks, at about $1.60 per optimised prompt (over 22x cheaper than validation-gated search). SkillOpt (2605.23904, May 24, Microsoft Research): treat the skill document as trainable, with reflection and bounded edits gated on held-out validation; paper reports wins over TextGrad, GEPA and human-written skills in 52 of 52 settings. The two papers' rankings of GEPA and SkillOpt differ by benchmark; DAIR reports both without reconciling them. *Test here:* run a one-pass log analysis over stored question, rung, SQL and outcome records to draft prompt rules, and keep a rule only if it improves a held-out question set. — [DAIR 2026 list](https://github.com/dair-ai/ML-Papers-of-the-Week/blob/main/years/2026.md)
- **General prompt hygiene.** Be specific, structure inputs, state the output format, use delimiters, decompose, use few-shot and CoT where reasoning is needed. No papers or tools cited. — [Optimizing Prompts](https://www.promptingguide.ai/guides/optimizing-prompts)
- Guide navigation confirms the technique set: zero-shot, few-shot, CoT, meta prompting, self-consistency, generated knowledge, prompt chaining, tree of thoughts, RAG, ART, APE, Active-Prompt, directional stimulus, PAL, ReAct, Reflexion, multimodal CoT, graph prompting. There is no chain-of-verification, DSPy or GEPA page in that list. — [site navigation, seen on](https://www.promptingguide.ai/agents/context-engineering)

### Inferences
- The Guide supplies citations and patterns, not evidence specific to SQL or clinical extraction; any gain here has to be measured locally.
- The classification case study and Structured Output Collapses Diversity (section 1) point the same way: a forced output template can change small-model behaviour, so reason-then-JSON versus JSON-only is worth one controlled comparison on the restatement prompt.
- With no optimisation tooling in place, the cheapest evidence-backed first step in DAIR's selections is CASD-style log analysis, not a search-based optimiser.

- Not opened: Reflexion, prompt chaining, meta prompting, Active-Prompt, function calling, hallucination-identification and information-extraction prompt pages, and the Guide's "extract with citations" material if any exists. No DAIR evidence on extraction with quoted citations was found.

## 5. What does DAIR say about RAG and document reading that bears on reading hundreds of clinical documents per question cheaply and verifiably?

### Takeaway
DAIR's standing RAG page is a 2024-era survey digest (chunking, hybrid search, reranking, compression, adaptive retrieval, RAGAS-style metrics) with paper citations and few numbers. The 2026 papers it highlighted are more relevant to this system: parallel one-chunk readers under a lead agent, explicit evidence state, decision-model navigation of a document hierarchy, table-of-contents addressing, and plain text search inside a good harness. None of them is clinical, and none addresses quote-verified extraction directly.

### Cited Findings

**DAIR's RAG pages (survey digest; papers cited by DAIR)**
- Evaluation: three quality scores (context relevance, answer faithfulness, answer relevance) and four abilities (noise robustness, negative rejection, information integration, counterfactual robustness); benchmarks RGB (arXiv:2309.01431) and RECALL (arXiv:2311.08147); frameworks RAGAS (arXiv:2309.15217), ARES (arXiv:2311.09476), RaLLe (arXiv:2308.10633), TruLens. *Test here:* add a "negative rejection" set (questions whose answer is not in any document) and score the readers on correctly returning nothing. — [RAG for LLMs](https://www.promptingguide.ai/research/rag)
- Position effects: "Lost in the Middle" (arXiv:2307.03172) found performance drops when relevant content sits mid-context; reranking can move relevant chunks to the edges. *Test here:* vary where the quoted passage sits in the reader's input and measure extraction recall. — [RAG for LLMs](https://www.promptingguide.ai/research/rag)
- Compression: RECOMP (arXiv:2310.04408) summarises retrieved documents before generation; token elimination (arXiv:2310.13682) is reported at up to 62.2% lower runtime for a 2% performance drop. — [RAG for LLMs](https://www.promptingguide.ai/research/rag)
- Long documents: RAPTOR (arXiv:2401.18059) builds a tree of recursive summaries and retrieves across levels; arXiv:2310.03025 found a 4K-context model with retrieval comparable to a 16K fine-tuned model on long-context tasks. — [RAG for LLMs](https://www.promptingguide.ai/research/rag)
- Adaptive retrieval: FLARE (arXiv:2305.06983) retrieves on low-confidence tokens; Self-RAG (arXiv:2310.11511); CRAG (arXiv:2401.15884) adds a retrieval evaluator; self-knowledge guided retrieval (arXiv:2310.05002). Query rewriting: HyDE (arXiv:2212.10496), Query2Doc (arXiv:2303.07678), step-back (arXiv:2310.06117). LLM as reranker for hard samples (arXiv:2303.08559). Hybrid keyword plus semantic search and small-to-large recursive retrieval are described without citations. — [RAG for LLMs](https://www.promptingguide.ai/research/rag)
- Chunking: match chunk size to the embedding model; fine-tune embeddings for specialised domains. — [RAG for LLMs](https://www.promptingguide.ai/research/rag)
- Faithfulness: Wu et al. 2024 (arXiv:2404.10198). Per DAIR's page: correct retrieved content fixes most model errors (94% accuracy); when retrieved content is wrong and the model's prior is weak, the model tends to repeat the wrong content; the further modified content deviates from the prior, the less likely the model is to adopt it. *Test here:* seed a reader's input with a document containing a plausible wrong value and check whether the quote requirement and number check catch it or pass it through. — [RAG Faithfulness](https://www.promptingguide.ai/research/rag-faithfulness)

**2026 papers DAIR highlighted** ([2026 list](https://github.com/dair-ai/ML-Papers-of-the-Week/blob/main/years/2026.md))
- **PARSER** (2609.06702, Sep 7): a bank of lightweight frozen subagents, each bound to one chunk, reads the whole document in parallel; a lead agent broadcasts a query, gathers evidence and issues deeper follow-up queries over several rounds. Paper reports a 4B system beating the strongest sequential-memory baseline by 5.7 points on average and 12.0 points at 896K tokens, and robustness to evidence position and order. *Test here:* cascaded readers as parallel per-document workers with a second scatter round driven by what the first round found; compare recall and cost against the current cascade.
- **LongHarness** (2610.13075, Oct 12): for corpora of 100M tokens; names two failure modes (unbounded exploration, evidence-state drift) and keeps evidence and conclusions as explicit linked state where open conclusions drive the next retrieval. Paper reports exact match on OfficeQA Pro rising from 15.8% to 60.2% (V1) and 4.4% to 61.1% (V2) with the same model. *Test here:* keep an evidence table (claim, quote, document, date) outside the model context and feed the model only open claims.
- **DecisionRAG** (2610.35868, Oct 26): Cornell and ASAPP. A decision model scores all candidates at each level of a topic-to-document-to-passage hierarchy in one forward pass with no generation. Paper reports +13.8 R@1 on MultiDoc2Dial and +17.4 Hit@1 on Natural Questions over dense retrieval plus an 8B reranker, at 0.7 to 1.8 seconds and 0.2 to 2.3 cents per query; judging candidates jointly adds 7.7 and 6.5 points over judging them separately. Limitation stated: depends on a well-organised hierarchy; a branch pruned early stays lost. *Test here:* use the typed-judgment classifier as the first document filter (patient, then document type, then document) and measure recall of documents the full reader would have quoted.
- **STAIR** (2609.03874, Sep 7): IBM. Address long documents by their table of contents instead of length-based chunks. Paper reports Recall@1 82.6% versus 59.5% BM25 and 68.7% DPR on a book benchmark. *Test here:* chunk clinical documents by section header (assessment, plan, medications) and route readers to sections by header.
- **Is Grep All You Need?** (2605.15184, May 11): in coding agents, text search inside a good harness matches or exceeds embedding retrieval, and the harness matters more than the retrieval primitive. *Test here:* keyword and code-list prefilter before any reader, with embeddings only as a recall backstop; measure missed documents.
- **The Efficiency Frontier** (2605.23071, May 24): which of retrieval or preprocessing wins depends on reuse count. Paper reports about 25% fewer effective tokens at comparable performance on 5,000 HotpotQA instances and over 50% lower token cost for amortised compression versus full context. *Test here:* compute break-even reuse for pre-extracting structured facts per document once versus reading on demand per question.
- **Context Compaction** (2611.05306): reading long inputs selectively with compaction as fallback matches or beats full-input baselines in almost every case tested. See section 1.
- **Skill-RAG** (2604.15771, Apr 19): retrieve only when a probe predicts failure, and route by failure type. **When to Retrieve During Reasoning** (2604.26649, Apr 26): inject evidence mid-reasoning. **MASS-RAG** (2604.18509, Apr 19): separate agents for retrieving, assessing relevance and synthesising. **A-RAG** (2602.03442, Feb 2): give the model hierarchical retrieval interfaces and let it choose granularity and when to stop. First lines only for these four.
- **Progressive Disclosure, Measured** (2607.17598): packaging a long document for staged loading helps only when the harness navigates raw text poorly. See section 1.
- Titles only: Coding Agents as Long-Context Processors (2603.20432), AgentIR (2603.04384), UniversalRAG (Jan 12), OpenScholar (Nature, Feb 2), WFM wiki foundation model (2609.18182); 2025: CLaRa (2511.18659), FACTS Leaderboard (2512.10791).

**Academy**
- "Introduction to RAG" is archived and Pro (38 lessons); agentic RAG lessons sit inside the Pro n8n course. Content not read. — [catalogue](https://academy.dair.ai/courses)

### Inferences
- The cheapest evidence-backed design for hundreds of documents per question, combining DAIR's selections: deterministic text and metadata prefilter, a probability-returning cheap filter over a hierarchy (DecisionRAG), parallel one-document readers (PARSER), and an external evidence table (LongHarness). The existing quote requirement gives the verifiability these papers do not address.
- Hierarchical pruning has a stated irrecoverable-miss risk; in a clinical setting recall of the filter stage should be measured before it is trusted, with an escalation path for low-confidence prunes.
- The RAG Faithfulness finding implies a quote check confirms that text was present, not that it was correct; conflicting documents need an explicit rule (most recent, or surface both).

### Gaps
- No DAIR material found on clinical-document RAG, on extraction with mandatory quotes, or on verifying quoted spans.
- DAIR's RAG research page reflects the 2023 to 2024 survey literature; I found no updated 2026 DAIR-authored RAG guide on public pages.
- Paid RAG course content was not read. Summaries for the "first lines only" and "titles only" entries were not extracted in full.
